# 生成模型到底该先生成什么？我翻了近 80 篇论文，也踩了几个月的坑

> 作者：挑灯看剑｜ 全文约 6520 字
> 从 AR、Masked Diffusion 到逐 patch 异步去噪：生成顺序可能是生成模型下一个值得被单独研究的设计轴。

---

## TL;DR

原来以为，"生成顺序"无非是左到右、随机顺序，或者换一条 diffusion noise schedule。把近几年的论文串起来，再结合自己在数独、时序、迷宫和图像上的实验，我现在更愿意这样定义它：

> 生成顺序是一套作用在部分生成状态上的控制策略：下一步更新哪里、并行更新多少、每个变量推进多少、已生成内容能不能撤回，以及什么时候停止。

目前比较站得住的结论有五个：

1. 理想模型里，不同合法分解可以对应同一个联合分布；现实模型里，顺序会决定模型先解决容易的条件问题，还是先啃最难的骨头。
2. 顺序和并行不是一回事。选对下一批 token，不代表它们适合相互独立地同时生成。
3. 任意顺序很诱人，但"什么状态都能去噪"的通用模型，常常不如沿固定路径训练的专用模型。
4. 真正有价值的不只是"先生成谁"，还有 remask、renoise、回退和重新提交。
5. 连续空间已经从一个标量时间走向patch/token/subspace 级异步时间，但稳定、可解释、可迁移的闭环 planner 仍未解决。

## 1. 为什么值得研究

我们通常按模型家族介绍生成模型：AR 做 next-token prediction，Diffusion 从噪声逐步去噪，NAR 并行填充，Flow 学连续运输。

但换个角度，它们都在回答同一个问题：在已经知道部分信息的情况下，下一步补什么？

文本模型默认左到右，不代表所有语言任务都天然适合左到右；图像 AR 使用 raster scan，也不代表图像应该从左上角画到右下角；标准 diffusion 让所有像素共享同一个时间，更不代表所有区域难度相同。这些选择往往是有效的工程先验，但未必是数据唯一合理的生成路径。

当模型只需要一次性生成完整样本时，固定顺序还能工作。可一旦我们要求它补全、编辑、推理、回滚、多模态生成，并在有限预算下决定哪里多算几步，固定左到右或同步 schedule 就显得太死板了。

所以，生成模型除了"学什么分布"，还存在另一个常被忽略的问题：以什么执行顺序调用已经学到的条件预测能力。过去它被塞在 sampler、mask schedule 或 decoding heuristic 里，现在正在逐渐成为独立研究对象。

## 2. 生成顺序到底是什么

最直观的定义是：同一样本里，不同变量到达最终值的先后顺序。比如数独先填约束最强的格子，图像先形成大结构再补纹理。

但这个定义还不够严谨。随机生成里，一个 token 可能中途碰巧等于最终答案，后面又被改掉。真正可测的通常是它最后一次变化、正式 commit，或之后持续稳定的时间。

而且，顺序并不是一个简单 permutation。一次生成一个 token 和一次生成十个 token，即使排序相同，误差也可能完全不同；允许 remask 和不允许 remask，也不是同一个问题。

一套完整策略至少要回答：

- 更新哪个 token、patch、图节点、尺度或频带；
- 一次更新一个，还是一个动态集合；
- 直接完成，还是只降低部分噪声；
- 已提交内容能否 remask、edit 或 renoise；
- 根据固定步数，还是稳定性、置信度、verifier 决定停止。

可以用高维进度向量 **τ** 表示各变量的去噪程度。标准 diffusion 是所有坐标共享时钟；token-wise AR 每次只推进一个坐标；block diffusion 是 block 间因果、block 内迭代；更一般的模型，则需要 planner 根据当前状态选择下一步的 **τ**。

但这只是统一研究语言，不代表所有模型都能被同一条线性插值严格等价地描述。真正要分清的是：一篇工作改了概率分解、前向破坏路径，还是推理策略。

## 3. 这条线怎么发展起来的

### 第一阶段：固定顺序不是天经地义

多尺度 AR 说明图像可以先生成粗尺度，再并行补细尺度；XLNet 用 permutation LM 弱化单一方向偏置；Insertion Transformer 直接把动作改成"在任意位置插入 token"。

这一阶段最重要的认识是：AR 的本质是条件分解，不是左到右。

### 第二阶段：模型具备 any-order 条件能力

Mask-Predict、MaskGIT、any-order AR、σ-GPT、RandAR 等方法，让同一个模型处理不同 mask pattern 或位置请求。模型不再只回答"下一个位置是什么"，而能回答"给定当前部分上下文，指定位置应该是什么"。

这为 planner 提供了底座，也暴露出一个现实问题：训练分布要覆盖多少 mask/order？随机顺序究竟学到了灵活生成，还是只起到正则化？模型容量会不会被大量条件任务摊薄？

### 第三阶段：planner 和 denoiser 被明确拆开

MaskGIT 的 confidence-first 是实用的早期启发式；DDPD、P2 等工作进一步把生成拆为两个角色：

- denoiser 回答"值是什么"；
- planner 回答"现在该更新哪里，旧答案要不要撤回"。

生成由此不再是一次性排列，而接近闭环控制：状态不好就remask，局部承诺不可靠就重算，预算不足就调整提交数量。

### 第四阶段：顺序、并行、修订和训练对齐被放到一起

2025 年之后，研究者逐渐意识到，"easy-first 有效"只是半个答案。一次并行提交多个 token，相当于近似忽略它们之间的条件依赖；即使每个 token 单独看都很有把握，放在一起也可能冲突。

同时，planner 会改变推理时访问的状态分布。如果训练总看随机 mask，部署却只走 easy-first 或学习路径，denoiser 可能在处理训练时很少见的状态。于是 planner-aware training、sampler-matched training、顺序和 token 联合搜索、动态 set/block、visible-to-visible revision 成为新主线。

连续 diffusion 也在走类似路线：MuLAN 使用逐维噪声速度，Diffusion Forcing 给 token 独立噪声水平，Rolling Diffusion 使用异步时间窗口；2026 年的 Patch Forcing 和 AsyncPatch 又把异步时间推进到图像 patch 或 latent token。

## 4. 现有论文真正证明了什么

### 4.1 有限模型下，顺序确实重要

如果每个条件分布都完全准确，采样也无误，不同合法分解可以得到同一个联合分布。现实模型显然达不到这个极限。

模型对不同条件问题的误差并不均匀。有些位置在当前上下文下几乎确定，有些位置必须等全局结构出来。好的顺序，本质上是在管理近似误差：先解决可靠问题，把结果变成上下文，再处理困难部分。

这也是 easy-first 在数独和结构任务中表现很强的原因。它未必是什么"人类推理顺序"，更像一种误差控制策略。Train for the Worst 的分析与实验也表明，模型误差越明显，顺序选择带来的收益往往越突出。

### 4.2 easy-first 有效，但 confidence 不是长期价值

置信度高，只表示模型此刻觉得自己更可能答对。它不等于这个变量对未来最有帮助，也不等于它与同批变量相互独立。

有时应该先生成最容易的位置；有时应该先生成信息增益最大、约束图最中心，或最能缩小后续搜索空间的变量。真正成熟的 planner 不能只优化即时正确率，还要考虑未来上下文价值。

### 4.3 顺序和并行度必须分拆

"下一个生成谁"是 order problem；"哪些变量可以一起生成"是 dependency problem。朴素并行解码会把同组 token 近似独立采样，而真实联合分布里它们可能强耦合。

组越大，速度越快，但不连贯和冲突风险越高。因此，策略不应只是取 top-k confidence，还要考虑组内依赖、验证成本和真实硬件收益。信息论分析进一步指出，因子化并行会产生独立于顺序选择的采样偏差，精确验证的成本又会随组内总相关快速上升。

### 4.4 任意顺序能力很贵

一个模型支持所有顺序，意味着它要处理非常广的部分上下文分布。mask 子集的组合空间是指数级的，训练不可能均匀覆盖；容量有限时，模型也会在通用性和专门化之间取舍。

所以很常见的结果是：random/any-order 训练获得了编辑、补全和灵活条件化能力，但固定路径 specialist 仍然更强。

我比较看好"先广后窄"：先让较宽覆盖的模型探索路径，再把顺序蒸馏给轻量 planner 或专用模型；至少也要让训练状态向部署 planner 的 occupancy 靠拢。

### 4.5 revision 可能比"先后"更重要

如果不允许回退，早期一次错误会永久改变后续条件分布。允许 remask、edit、renoise 后，问题就从"找完美排列"变成"边走边检查，必要时撤回"。

但 revision 不是越多越好。它增加 NFE 和延迟，还可能在 commit/remask 间震荡。任何"remask 有效"的结论，都应该匹配模型调用、wall-clock 和验证开销。

### 4.6 "低频先、高频后"不是 diffusion 定律

标准图像 DDPM 经常先恢复低频，再补细节。更准确的原因是：自然图像频谱和白噪声前向过程共同作用时，高频 SNR 往往更早下降。

Fourier-space 的研究表明，改变频率相关的 corruption 后，这种趋势可以被拉平，而且在高频主导数据上可能更好。所以低频到高频是一种常见 inductive bias，不是 diffusion 的本体定律；频率层次也不能直接等同于语义层次。

### 4.7 学到的顺序不自动等于因果顺序

planner 先生成某些变量，可能只是因为它们条件熵低、tokenizer 更容易表示、模型在这些位置更准，或 reward 偏爱这种轨迹。

仅凭顺序可视化，就说模型发现了因果结构，证据不够。要做因果解释，至少要看干预后顺序是否随机制变化，能否迁移到另一个 denoiser，以及跨 seed/checkpoint 是否稳定。否则，"很像人类推理"更多是一种描述，而非因果结论。

### 4.8 如果只想抓住方法地图

把几十篇工作压缩一下，大致可以分成六类：

- **第一类**是固定结构路径，例如左到右、next-scale、frequency 和固定 block，优势是训练稳定，问题是先验可能选错。
- **第二类**是 random/any-order 训练，用更广的条件分布换补全和编辑能力，代价是容量被摊薄。
- **第三类**是 confidence/difficulty planner，便宜好用，但容易短视和失校准。
- **第四类**是 learned policy 或搜索，能够做状态依赖决策，却最容易把额外参数和推理算力混进"顺序收益"。
- **第五类**是连续向量时间与 learned forward path，表达力最强，也最容易不可辨识、同步坍缩或出现脉冲式更新。
- **第六类**是 revision/closed-loop，允许模型撤回旧承诺，更接近真正的推理过程，但需要可靠错误检测和停止机制。

我现在判断一篇"顺序优化"工作时，会先问四个问题：

- 它改变的是模型、路径，还是额外算力？
- 底层 denoiser 是否相同？
- 并行组内部的依赖如何处理？
- 得到的轨迹换模型、换 seed 后是否还成立？

这四个问题回答不清，结果再漂亮也很难说明真正学到了生成顺序。

## 5. 我的私货：失败实验带来的判断

这一节不是论文结论，是我在数独、时序、迷宫和图像实验里的阶段性经验。

### 5.1 不要一上来训练"全路径 foundation denoiser"

我最开始的想法很自然：既然推理时想自由选路径，训练时就随机采样每个维度的 noise level，让 denoiser 什么 **τ** 都见过。

实际效果通常不理想。固定标准路径的专用 denoiser 明显更强。问题不只是数据不够，而是随机高维状态里有大量很怪的条件：某些区域几乎完全干净，旁边接近纯噪声；模型容易利用 clean context 走捷径，或把容量浪费在部署时不会访问的状态上。

Patch Forcing 和 AsyncPatch 对 naive 独立时间采样的分析，也与这个现象一致：训练状态如果过度异质，模型会看到推理时不自然、信息量过高的部分上下文。

我的建议是：从可靠基准路径出发，只在附近加小扰动，先训练 local foundation denoiser，再逐渐扩大 trust region。不要把"覆盖整个路径空间"当成第一阶段目标。

### 5.2 联合训练可能更强，但更难解释

我试过的任务里，planner 和 denoiser 联合训练往往优于完全分开训练。planner 需要适应 denoiser 的真实误差，denoiser 也需要适应 planner 访问的状态。

但两者很容易共适应。planner 找到的可能不是数据更自然的顺序，而是某个特定 denoiser 最擅长、最容易钻空子的路径。换个模型，这条顺序可能立即失效。

所以只展示一条漂亮轨迹远远不够。至少要做固定 denoiser 换 planner、固定 planner 换 denoiser，以及跨 seed/checkpoint 迁移。顺序只有脱离原模型仍有效，才更像数据结构，而不是模型误差地图。

### 5.3 对完整 rollout 反向传播，未必划算

我也试过让 denoiser 和 planner 共同采样，外部 verifier 给最终 reward，再把梯度穿过完整 ODE rollout 更新两个网络。

它能训练，但相较于把两者合成自由度接近的Neural ODE，没有观察到明确优势；显存、梯度方差、长程 credit assignment 和数值稳定性却都更差。

因此我越来越倾向 simulation-free 或弱 rollout 的目标：先用局部去噪误差、信息增益代理或离线轨迹训练 planner，再少量端到端校准。除非 reward 只能在最终状态获得，否则没必要一开始就把整个采样器变成长链条 RL。

### 5.4 连续 schedule 的核心问题是不可辨识和坍缩

学到的路径很容易在空间上重新坍缩为共享 schedule，也容易在时间上变成开头或最后一步的脉冲式跳变。

加 entropy loss 能让路径看起来更丰富，但"更花"不等于更好。我的实验里，多样性提高后并没有稳定质量收益，也没有可重复的"布局—物体—纹理"规律，更多是随机、混乱、跨 seed 不稳定的时序图。

所以连续 planner 的正则不能只鼓励多样性。它需要局部平滑或有界更新、信息预算、路径复杂度惩罚、可逆动作的滞回，以及 discover-then-retrain 检验。

### 5.5 先证明可复现，再谈语义和因果

连续图像路径最吸引人的故事，是模型自己发现"布局—物体—纹理"。但在做出这种解释前，顺序至少应跨 seed、同义条件和 denoiser 稳定。

我现在会把目标分成两级：第一阶段只要求它在等算力下稳定提高质量或速度；第二阶段再研究它是否对应语义、频率、约束或因果。性能证据和科学解释不要混成一句话。

## 6. 接下来最值得做什么

**方向一：Local foundation denoiser + trust-region planner**

围绕标准 AR/diffusion 路径训练局部可变模型，planner 只能在受控邻域内调整；等模型稳定后再扩大路径自由度。这没有"全路径通用模型"那么浪漫，但更可能做成。

**方向二：从逐点排序升级为 dependency-aware set**

planner 不只给 token 打分，而是提出可并行提交的集合。目标同时考虑条件熵、组内总相关、验证成本和 wall-clock。不是只问"谁最容易"，还要问"谁和谁能安全地一起做"。Set Diffusion 把固定连续 block 推广到了位置和长度更灵活的 token set，但如何自适应提出集合仍然开放。

**方向三：discover–retrain–verify**

先用昂贵模型、搜索或 verifier 找轨迹；再蒸馏为轻量 planner，或沿这些路径重训练 specialist；最后移除昂贵搜索，看收益能否保留。只有重训练后仍然更好，才能说明发现的是更合适的学习或生成路径，而不只是 test-time compute 堆出来的结果。

**方向四：把 commit 和 revise 分开**

"生成新内容"和"检查旧承诺"是两种决策。一个 head 负责 proposal，另一个 head 决定哪些承诺要撤回，并加入 hysteresis 避免反复震荡。评测也应增加错误发现 precision、平均回退深度、循环率和无效 revision 次数，而不只看最终 FID、PPL 或 accuracy。

**一个可信的实验矩阵：**

1. 固定 denoiser，只换 random、confidence、learned、search planner；
2. 固定 planner，对比通用训练、planner-aware 训练和沿发现路径重训练；
3. 匹配 NFE、FLOPs、wall-clock、缓存和 verifier 调用；
4. 报告跨 seed、checkpoint 和模型的顺序稳定性；
5. 做 ID→OOD、短→长、低分辨率→高分辨率迁移；
6. 同时记录质量、提交轨迹、路径熵、revision 次数和失败循环。

否则，很容易把额外计算、额外网络或 sampler artifact 写成"生成顺序带来的提升"。

## 7. 最后

回头看这条研究线，我觉得最有意思的并不是再发明一种 AR 或 diffusion，而是把一个过去被默认的变量拿出来：

> 模型学会了大量条件预测能力之后，究竟应该按什么顺序使用它们？

今天很多生成模型内容能力很强，执行策略却相当原始：左到右、固定 block、统一时间、top-k confidence、固定步数。它有点像一个知识很多的人，但做题永远按题号写，写错了也不回头。

生成顺序真正想补的，是这一层"怎么做"的能力：先解决哪部分，哪些可以并行，什么时候应该怀疑自己，哪里值得多花算力，什么时候可以停。

我不觉得会有一条适用于所有数据的黄金顺序。更可能的答案是：顺序依赖表示、模型误差、任务约束和推理预算。也正因为如此，它更像 planner 或 controller，而不是一条固定 schedule。

对我来说，下一步真正值得追的，不是一张漂亮的去噪热力图，而是一个能经得住三个问题的系统：

- 换个模型，这条顺序还有效吗？
- 相同算力，它真的更好吗？
- 沿该路径重训练后，优势还能保留吗？

如果三个答案都是"是"，生成顺序就不再只是 sampler 技巧，而可能成为和 architecture、objective 同等级的设计轴。
