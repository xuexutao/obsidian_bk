# π0：视觉语言动作流模型与系列演进

## 基本信息

- **作者**：Kevin Black、Noah Brown、Danny Driess、Adnan Esmail、Michael Equi、Chelsea Finn、Niccolo Fusai、Lachy Groom、Karol Hausman、Brian Ichter、Szymon Jakubczak、Tim Jones、Liyiming Ke、Sergey Levine、Adrian Li-Bell、Mohith Mothukuri、Suraj Nair、Karl Pertsch、Lucy Xiaoyang Shi、James Tanner、Quan Vuong、Anna Walling、Haohuan Wang、Ury Zhilinsky（Physical Intelligence 团队，通讯邮箱 research@physicalintelligence.company）
- **机构**：Physical Intelligence（San Francisco, California, USA）
- **发表**：arXiv 2410.24164（2024-10），RSS 2025
- **项目页**：<https://physicalintelligence.company/blog/pi0>
- **代码**：<https://github.com/Physical-Intelligence/openpi>
- **原文 PDF**：<https://arxiv.org/pdf/2410.24164>

## 一句话结论

π0 把动作建模为**连续流**（continuous flow）而非离散 token：它在一个 3B 参数的 PaliGemma 视觉-语言模型（VLM）骨干之上挂一个 flow matching 动作专家（action expert，DiT 结构），输出 50 步高频连续动作 chunk，并在 7 种机器人本体、68 个任务、约 10,000 小时数据上联合预训练，实现 zero-shot 跨 embodiment 操控；π0 由此开创了"连续 flow matching VLA"这一范式，与 OpenVLA 的离散 token 路线并列，其后续系列（π0-FAST、π0.5、π0.7）持续抬升通用机器人基础模型的能力天花板。

## 1. 研究背景与问题定义

### 1.1 研究问题

机器人学习一直试图回答一个朴素但极其困难的问题：能不能训出一个"通用机器人策略"（generalist robot policy / robot foundation model），像语言模型之于文本那样，让同一个模型在多种机器人、多种任务上直接工作？π0 把这个问题拆成三层障碍——**数据、泛化、鲁棒性**——并指出它们的根子在于：机器人动作天然是**高频、连续、高维**的，而此前主流的大模型迁移路径（把 VLM 微调成 VLA）几乎都把动作压成**离散 token**，这一压就把机器人控制最本质的东西丢掉了。

### 1.2 现有方法的瓶颈

按照论文的定位，2024 年的 VLA 路线在动作表示上有两难：

- **离散 token 路线（RT-2、OpenVLA）**：借助预训练 VLM 的语义先验，把动作量化成离散 token 用自回归方式生成。优点是有 Internet 级视觉-语言知识；缺点是动作量化会破坏连续性、丧失平滑性，且自回归逐 token 生成的速度撑不起 50 Hz 级别的灵巧操控。论文里的 OpenVLA 基线在 out-of-box 任务上全线落后，主因正是其"自回归离散化架构不支持 action chunk"。
- **连续扩散/流路线（Diffusion Policy、Octo 等）**：用扩散或流匹配建模连续动作分布，能输出平滑的高频动作，但缺少 VLM 预训练带来的语义与跨任务泛化能力，表征容量也受限。

π0 的出发点很直接：**这两件事应该合并**。既然 VLM 骨干能提供语义理解和跨任务泛化，flow matching 能提供连续、高频率、可表达多模态的动作分布，那就把它们拼成一个模型——VLM 负责"看懂与听懂"，flow matching 动作专家负责"怎么动"。

### 1.3 本文核心贡献

1. 提出**基于 VLM 预训练的 flow matching VLA 架构**：以 PaliGemma-3B 为骨干，附加一个从零初始化的 flow matching 动作专家，把动作建模为连续流；
2. 确立"**<span style="color: red">预训练 / 后训练</span>**"分离的机器人基础模型 recipe：先在跨本体、多任务的大杂烩数据上预训练，再针对下游任务做高质量数据的微调，对应 LLM 里的 pre-training / post-training 范式；
3. 在 **7 种机器人配置、68 个任务、约 10,000 小时** 的混合数据（专家遥操作 + 自主收集）上验证了 **zero-shot 跨 embodiment 操控**：一个模型开箱即用，直接 prompt 或微调就能完成洗衣折叠、清理桌面、组装纸盒等长程灵巧任务；
4. 开源了 openpi 代码库，为后续 π0-FAST / π0.5 / π0.7 系列演进奠定工程基座。

## 2. 任务定义与输入输出

### 2.1 输入、输出与假设

- **输入**：当前图像观测 $\mathbf{o}_t$（每本体 1–3 个相机视角，含腕部相机）与语言指令 $\ell$（如 "fold the shirt"）。<span style="color: red">图像经 VLM 内的 SigLIP 视觉塔编码，语言经 Gemma 语言塔编码</span>；
- **输出**：未来动作序列 $A_t = [a_t, a_{t+1}, \ldots, a_{t+H-1}]$，其中 $H=50$，是 action chunking（Zhao et al. 的 Diffusion Policy 范式）在 VLA 上的移植；
- **核心假设**：连续、高频的动作分布用 flow matching 表达，比离散 token 更贴近真实机器人控制的物理结构；而 VLM 预训练带来的语义先验，能让这个连续动作模型获得跨任务、跨本体的泛化能力。<span style="color: red">二者在同一个骨干里共享表征，是 π0 成立的前提</span>。

### 2.2 关键符号与目标函数

π0 动作专家采用 **conditional flow matching**（Lipman et al. 2023；Rectified Flow, Liu et al. 2023）。对动作 chunk 中每个动作分量 $a$，定义时间 $s \in [0,1]$ 上的线性概率路径：

$$a_s = s\, a_1 + (1-s)\, a_0, \qquad a_0 \sim \mathcal{N}(0, I)$$

其中 $a_1$ 是目标动作，$a_0$ 是高斯噪声，条件向量场恒为 $u(a_s \mid a_1) = a_1 - a_0$。动作专家 $f_\theta$ 以 VLM 骨干输出的视觉-语言 token 表征 $c$ 为条件，预测向量场 $v_\theta(a_s, s, c)$，训练目标为：

$$\mathcal{L}_{FM}(\theta) = \mathbb{E}_{s,\, a_0,\, a_1} \left\| v_\theta(a_s, s, c) - (a_1 - a_0) \right\|^2$$

推理时从 $a_0 \sim \mathcal{N}(0,I)$ 出发，沿学到的向量场积分（ODE 求解，如 Euler 法）从 $s=0$ 推到 $s=1$：

$$\frac{d a_s}{ds} = v_\theta(a_s, s, c) \;\Longrightarrow\; a_1 = a_0 + \int_0^1 v_\theta(a_s, s, c)\, ds$$

得到的 $a_1$ 即 50 步动作 chunk。相较扩散模型 DDPM 预测噪声 $\boldsymbol{\epsilon}$，flow matching 直接回归速度场，去噪步数可大幅减少，且生成路径更平滑，契合灵巧操控对连续性与高频的要求。

## 3. 核心方法

### 3.1 总体框架

π0 的框架可以概括为一句话：**用一个预训练 VLM 骨干做"感知与理解"，挂一个 flow matching 动作专家做"连续动作生成"，二者共享上下文、联合训练**（Figure 1）。**<span style="color: red">VLM 骨干权重复用 PaliGemma 的 Internet 预训练，动作专家从零初始化</span>**。这样既继承了大模型的语义世界知识，又绕开了"动作必须离散化"的约束，一次生成 50 步连续动作块以支持高频控制；实际 Hz 由本体数据与控制接口决定。

![](assets/π0%20-%20视觉语言动作流模型与系列演进/figures/01-overview.png)

> **图 1：π0 模型与系统总览。** 一个预训练 VLM 骨干 + 跨本体数据集（多种灵巧操作任务）构成基座；通过附加一个独立的动作专家，用 flow matching 生成连续动作，实现精确而流畅的操作技能。模型既可以直接根据 prompt 执行任务，也可以在高品质数据上微调，解锁多阶段的复杂长程任务（如折叠多件衣物、组装纸盒）。
> 来源：论文 Figure 1，第 1 页，<https://arxiv.org/abs/2410.24164>

### 3.2 架构细节：PaliGemma 骨干 + 动作专家

π0 以 PaliGemma 3B 级 VLM 为初始化：SigLIP So400m/14 处理图像，Gemma 2B 语言专家处理文本；另加约 311M 的动作专家。论文图可以把它抽象成“VLM 条件 + action expert”，但官方 openpi 的代码结构更具体：

1. 图像与文本组成 **prefix expert**，residual width 为 2048；
2. 连续 state 与 noisy action/time 组成 **suffix action expert**，residual width 为 1024；
3. 两个 expert 在每一层各自计算 Q/K/V，再沿 token 轴拼接做一次共享 self-attention，之后切回各自序列并进入各自 FFN；
4. prefix/suffix block mask 保证 prefix 不读取动作，而动作读取完整视觉语言条件和整个动作块。

因此它不是“VLM 完整前向后把单个输出喂给外挂 cross-attention DiT”的严格串联，也不是 SigLIP 与 Gemma 之间另有一个独立 cross-attention 层。准确实现见 §3.8。动作专家仍从零初始化并以 flow matching 训练，VLM/动作专属 FFN 参数分离，而共享 attention 负责跨模态交换。

![](assets/π0%20-%20视觉语言动作流模型与系列演进/figures/02-architecture.png)

> **图 2：π0 框架总览。** 左半是预训练数据混合：既包含自采的灵巧操作数据，也包含开源数据；中间是模型：VLM 骨干权重由 PaliGemma 初始化，附加一个小型动作专家处理机器人状态与动作；右半是产物：得到的 π0 模型可以控制具有不同动作空间的多种机器人本体，完成各种任务。
> 来源：论文 Figure 3，第 4 页，<https://arxiv.org/abs/2410.24164>

### 3.3 Flow matching 动作头

这是 π0 与所有离散 token VLA（RT-2、OpenVLA）分道扬镳的地方。π0 的动作专家不做 token 离散化，而是把动作 chunk 的每个维度视为连续变量，用第 2.2 节的 conditional flow matching 直接建模其分布：

- 训练时，从数据里采样真实动作 chunk 作为 $a_1$，采样噪声 $a_0 \sim \mathcal{N}(0,I)$ 和 flow 时间 $s$，构造 $a_s = s a_1 + (1-s) a_0$，让动作专家以 VLM token 表征为条件回归速度场 $(a_1 - a_0)$；
- 推理时，从噪声出发用 ODE 积分逐步把噪声"流向"目标动作分布。

论文强调 flow matching 相较扩散在灵巧操控上的两个优势：一是**生成路径更直、去噪步数更少**，便于实时控制；二是<span style="color: red">能建模多模态动作分布</span>——同一个观测下可能存在多种正确动作（抓左边还是抓右边），流匹配的连续分布天然能表达这种多模态性，而离散自回归 token 会在这里产生退化。这一设计让 π0 能适配论文中的高频灵巧控制场景；但 `H=50` 是 chunk 长度，不是写死在模型中的 50 Hz。

### 3.4 50 步 action chunk 与高频控制

π0 沿用 Diffusion Policy 的 action chunking 思想，取 $H = 50$：一次推理输出未来 50 步动作，执行时按控制频率逐步下发，到点再重新推理。这样做的意义是：

- **缓解短视**：单步预测容易在局部抖动作，50 步 chunk 让动作序列在时间上自洽，适合需要连续协作的折叠、装配类任务；
- **匹配高频**：一次生成 50 步连续动作，避免逐 token 自回归成为控制瓶颈；具体控制频率按本体设置，而非由 `H=50` 自动决定。

### 3.5 多本体联合训练与跨 embodiment 泛化

π0 的训练数据覆盖 **7 种不同的机器人配置**（单臂 UR5e、双臂 UR5e、Franka、移动底座等）与 **68 个任务**。不同本体的动作空间差异巨大——关节数不同、末端执行器不同、自由度不同（从 6-DoF 单臂到双臂灵巧手）。π0 的处理方式是把**动作空间归一化到每个本体自己的坐标体系内**，让 VLM 骨干学到与本体无关的"任务语义与操作意图"，动作专家再针对具体本体输出相应维度的动作。这是"一个模型控制多种机器人"的工程关键：**语义层共享，动作层本体化**。论文的实验显示，联合训练得到的单一 π0 模型可以 zero-shot 迁移到训练中见过的各种本体上执行任务，而不需要针对每个本体单独训一个策略。

### 3.6 训练流程：预训练 / 后训练分离

π0 明确地把 LLM 的 pre-training / post-training 范式搬到机器人领域：

- **预训练阶段（pre-training）**：在约 10,000 小时、跨 7 本体 68 任务的混合数据（专家遥操作 + 自主收集）上联合训练完整 π0（VLM 骨干 + 动作专家），目标是学一个通用的"能看懂、能听懂、能动"的基座模型；全量训练 700k steps；
- **后训练阶段（post-training / fine-tuning）**：针对具体下游任务（如洗衣折叠、清理桌面、组装纸盒）用高质量数据微调，解锁更复杂的多阶段长程行为，并可搭配一个高层 VLM 策略做任务规划。

论文特别强调这种分离的价值：预训练阶段给了模型跨任务、跨本体的"通识"，后训练阶段只需少量高质量数据就能把它拉到一个具体任务的高水准，数据效率远超从零训练。

### 3.7 推理流程

一次完整推理：当前观测 $\mathbf{o}_t$ + 语言指令 $\ell$ → SigLIP / Gemma 编码 → VLM 骨干输出上下文 token → 动作专家以 token 为条件做 flow matching 去噪 → 得到 50 步动作 chunk → 按目标机器人的控制频率逐步执行。需要特别纠正：**50 是 chunk 的时间步数，不自动等于所有本体都以 50 Hz 控制**；实际控制频率由数据与机器人接口决定。

#### 3.8.2 默认输入与 action-dim padding

【源码事实】`Pi0Config()` 的关键默认值是：

- `paligemma_variant="gemma_2b"`：Gemma residual width 2048、18 层、8 heads、head dim 256；
- `action_expert_variant="gemma_300m"`：expert width 1024、18 层、8 heads、head dim 256，约 311M 参数；
- SigLIP `So400m/14`，输入 `224×224`，每图 $16×16=256$ token；
- `action_dim=32`、`action_horizon=50`、`max_token_len=48`、dtype bf16；
- 标准 image keys 固定为 `base_0_rgb/left_wrist_0_rgb/right_wrist_0_rgb`。缺失视角应由数据 adapter 提供占位图并把对应 image mask 置 false，而不是改变模型结构。

【源码事实】原始机器人 state/action 的最后一维 $D_r$ 若小于 32，`PadStatesAndActions` 直接补零：

$$s∈\mathbb R^{B×D_r}\rightarrow \tilde s∈\mathbb R^{B×32},\qquad
A∈\mathbb R^{B×50×D_r}\rightarrow \tilde A∈\mathbb R^{B×50×32}.$$

必须注意：π0 的 canonical `compute_loss` **没有逐维 action validity mask**，最终 MSE 对 32 维取平均。因此补零维的 target 是 0，也会参与训练；推理后再由 output transform 反归一化并裁回 $D_r$。这与 VITRA/OpenWAM 的显式逐维 mask 不同。

#### 3.8.3 按真实 forward 顺序的全链路张量表

代码始终保留 3 个相机槽，因此 prefix 物理长度固定为 $P=3\times256+48=816$；$K≤3$ 仅表示有效相机数，并决定 image mask 中有效视觉 token 的数量。文本有效长度为 $L≤48$，无效图像与 text padding 均由 mask 屏蔽。

| 顺序 | 张量与 shape | 变化原因与证据 |
|---:|---|---|
| 1 | 每路 uint8/float RGB `[B,H_0,W_0,3]` → `[B,224,224,3]` | 【源码事实】等比 resize+pad；uint8 转 float32 `[-1,1]`；训练时非 wrist 图像做 crop/rotate/jitter |
| 2 | prompt → ids/mask `[B,48]` | 【源码事实】π0 默认 max token 48；$L$ 是动态有效长度，其余为 padding |
| 3 | raw state/action → `[B,32]` / `[B,50,32]` | 【源码事实】按数据统计归一化后尾部补零到模型统一宽度 |
| 4 | SigLIP 每图 `[B,224,224,3] → [B,256,2048]` | 【配置推导】patch 14 得 256 token；`num_classes=paligemma_config.width=2048` 已完成视觉到 Gemma 宽度投影 |
| 5 | 3 个固定图像槽 concat + text embed → prefix `[B,816,2048]` | 【源码事实】顺序为 base、left wrist、right wrist、language；缺失相机仍保留占位 tokens，但由 image mask 屏蔽；prefix AR 标记全为 false |
| 6 | state linear `[B,32] → [B,1,1024]` | 【源码事实】初代 π0 把连续 proprio 作为 suffix 首 token；π0.5 分支才把 state 离散进语言 |
| 7 | action linear `[B,50,32] → [B,50,1024]` | 【源码事实】每个未来动作步一个 expert token |
| 8 | flow time $t\in[0,1]$：`[B] → [B,1024] → [B,50,1024]` | 【源码事实】正余弦 embedding 复制 50 次，与 action token 沿 channel 拼成 2048-D |
| 9 | action+time MLP `[B,50,2048] → [B,50,1024]` | 【源码事实】两层 MLP 融合 noisy action 与当前 flow time |
| 10 | suffix `[state(1),action(50)] = [B,51,1024]` | 【源码事实】state 和动作专家拥有不同于 prefix 的 residual width |
| 11 | combined block mask `[B,P+51,P+51]` | 【源码事实】由 `cumsum(mask_ar)` 比较生成，具体可见性见下一小节 |
| 12 | prefix/suffix 各自 QKV → 8 heads×256 | 【源码事实】2048/1024 residual 分别投影到相同 head geometry，随后在 sequence 维拼接 |
| 13 | 18 层 shared attention + expert-specific FFN | 【源码事实】attention 让 action suffix 读取 PaliGemma prefix；VLM FFN 与 motor expert FFN 参数独立 |
| 14 | suffix output `[B,51,1024]` → 末 50 token | 【源码事实】state token output 被丢弃，只保留动作 token |
| 15 | action out projection → $v_t=[B,50,32]$ | 【源码事实】预测 flow velocity，而非离散动作 token |
| 16 | loss target $u_t=\epsilon-A\in\mathbb R^{B\times50\times32}$ | 【源码事实】按 action dim 求均方，得到 `[B,50]`；训练器再跨时间/batch 聚合 |
| 17 | 推理 prefix prefill → KV cache | 【源码事实】SigLIP/Gemma prefix 每个 action chunk 只计算一次 |
| 18 | 10 次 suffix denoise，每步仍输出 `[B,50,32]` | 【源码事实】Euler `dt=-0.1`，从 $t=1$ 高斯噪声走到 $t=0$ 动作分布 |
| 19 | unnormalize + slice → `[B,50,D_r]` | 【源码事实】只把目标本体真实维度交给机器人执行 |

#### 3.8.4 prefix/suffix attention mask 的精确含义

源码的 `mask_ar` 不是普通 causal 三角阵。prefix 全为 false；suffix 中 state 标一次 true，action block 的首 token 再标一次 true，其余 49 个 action token 为 false。累积和因此形成三个 block：

1. **prefix（图像+文本）**：内部全双向；prefix query 看不到 state/action；
2. **state token**：能看全部 prefix 和自身，但看不到 action；
3. **50 个 action token**：能看全部 prefix、state 和整个 50-token action block，动作块内部双向。

矩阵化写为：

$$
M=\begin{bmatrix}
\mathbf 1_{P×P} & 0 & 0\\
\mathbf 1_{1×P} & 1 & 0\\
\mathbf 1_{50×P} & \mathbf 1_{50×1} & \mathbf 1_{50×50}
\end{bmatrix}.
$$

所以 π0 不是“VLM 先独立输出一个 context，再由外挂 DiT cross-attend”的串联模型。官方 openpi 的真实结构是**PaliGemma prefix expert 与 action suffix expert 在每一层共享 self-attention，保留各自 residual/FFN 参数**；prefix/suffix mask 决定单向信息流。

#### 3.8.5 flow-matching 训练与 denoise 的代码约定

openpi 注释明确说明，其时间方向与论文记号相反。源码使用 $t=1$ 为噪声、$t=0$ 为数据：

$$t\sim0.999\,\mathrm{Beta}(1.5,1)+0.001,$$
$$x_t=t\epsilon+(1-t)A,\qquad u_t=\epsilon-A,$$
$$\mathcal L=\mathbb E\left[\|v_\theta(x_t,t,c)-u_t\|_2^2\right].$$

推理从 $x_1=\epsilon$ 开始，以 $\Delta t=-1/N$ 做 Euler：

$$x_{t+\Delta t}=x_t+\Delta t\,v_\theta(x_t,t,c),\qquad N=10,$$

最终返回 $x_0∈\mathbb R^{B×50×32}$。这与论文“从噪声流向动作”的物理含义完全等价，只是符号方向相反；复现时若把论文公式和源码 target 混用，会把速度场符号写反。

#### 3.8.6 代码—论文差异与复现建议

- **PaliGemma/SigLIP 的准确说法**：【源码事实】是 SigLIP So400m/14 + Gemma 2B text expert + 311M action expert，总体约 3.3B；“PaliGemma-3B”是模型家族/总规模简称，不等于语言塔本身 3B。
- **不是独立 cross-attention DiT**：【源码事实】双 expert 在每层把 QKV 沿 sequence 拼接做共享 attention；前文“VLM 输出喂给独立 DiT”是论文层面的简化图示，不能当代码结构。
- **50 步不等于 50 Hz**：【源码事实】config 只规定 horizon=50，没有规定硬件控制周期；部署频率来自 dataset adapter/robot loop。
- **padding 维有 loss**：【源码事实】32-D 尾部补零没有逐维 mask。新增本体时必须检查 normalization stats 的维度和 output slice，避免把真实维错位到 padding 槽。
- **公开代码不等于完整预训练 recipe**：【源码事实】openpi 提供模型、权重、微调与部分数据管线；README 对 full DROID 训练明确称“approximate open-source implementation”。论文 10k+ 小时私有混合数据及精确采样比例未完整开放，不能声称仅凭 repo 可从零复现论文 base。
- **最小 shape 断言**：默认三相机时检查 image tokens `3×256=768`、text slots 48、prefix 816、suffix 51、总 query 867；同时断言动作始终 `[B,50,32]`，最终 adapter 才裁为 $D_r$。
- **无法确认项**：【无法确认】论文最终 base checkpoint 的逐本体控制频率、各本体实际执行 chunk 长度/重规划间隔、10k 小时混合比例和完整预训练 optimizer schedule没有由该代码 revision 完整给出。

## 4. 数据集与实验设置

### 4.1 数据集与数据处理

π0 的预训练数据规模约 **10,000 小时**，由两部分构成：

- **专家遥操作数据**：人类操作员通过遥操作设备（space mouse、VR 手套等）采集的高质量示教，覆盖双臂折叠、精细抓取等灵巧任务；
- **自主收集数据**：机器人自主执行策略时采集的交互数据，量大但质量略逊，用于扩充分布与提升鲁棒性。

数据覆盖 **7 种机器人配置**（单臂 UR5e、双臂 UR5e、Franka、移动底座等）与 **68 个任务**，并混入部分开源机器人数据集。动作空间按本体归一化，视觉观测来自每本体 1–3 个相机。论文还指出洗衣折叠这类较难任务在混合里被**过采样（overrepresented）**，以强化模型在关键任务上的表现。

### 4.2 Baseline 与评价指标

- **Baseline**：OpenVLA（离散 token VLA 代表）、Octo（扩散策略，支持 action chunk）、π0-small（去掉 VLM 预训练的缩小版 π0，用于隔离 VLM 预训练的贡献）、以及只在 UR5e 数据上单独训练的 OpenVLA（UR5e only）；
- **评价指标**：归一化分数（normalized score），每个任务、每个方法跑 10 个 episode 取平均；完整成功记 1.0，部分成功按完成比例记小数（如 bussing 任务按正确归位物体的比例计分）。

### 4.3 实现细节

- **骨干**：PaliGemma-3B（SigLIP 视觉塔 + Gemma 语言塔）；
- **动作专家**：从零初始化的 transformer（DiT），规模小于 VLM 骨干；
- **动作 chunk**：$H=50$；控制频率由各本体数据/执行接口定义，不能由 horizon 反推为固定 50 Hz；
- **训练步数**：全量 700k steps；另训一个 160k steps 的 parity 版本与基线对齐训练量做公平比较；
- **flow matching**：线性路径 + 条件向量场回归，推理用 ODE 积分。

## 5. 实验结果

### 5.1 主要定量结果

π0 在 out-of-box（开箱即用、不做微调）评估上全线领先。5 个直接 prompt 任务——衬衫折叠（Shirt Folding, Bi-ARX）、清理桌面易/难（Bussing Easy/Hard, UR5e）、杂货装袋（Grocery Bagging, UR5e）、烤吐司（Toast, Bi-Trossen）——π0 在衬衫折叠和较易的清理任务上取得接近满分的成绩，且在所有任务上大幅超越 OpenVLA、Octo 与 π0-small：

- **OpenVLA 掉队**：因其自回归离散化架构不支持 action chunk，几乎无法处理这些高频连续任务；即使只在 UR5e 数据上单独训练，仍远低于 π0；
- **Octo 受限**：虽然支持 action chunk，但表征容量不足，无法与"大而强"的 π0 架构抗衡；
- **π0-small 的意义**：去掉 VLM 预训练的缩小版 π0 表现明显更差，直接证明了 VLM 预训练对动作模型泛化的核心价值；
- **parity 版本依然领先**：仅训练 160k steps（与基线训练量对齐）的 π0 仍胜过所有基线，说明优势来自架构与预训练本身，而非单纯的数据或训练时长。

![](assets/π0%20-%20视觉语言动作流模型与系列演进/figures/03-results.png)

> **图 3：微调数据量变化的性能曲线。** π0 即使在数据量较少时也能学会部分较简单的任务，随着高质量微调数据增加，性能进一步提升——这印证了"预训练打底 + 后训练提效"的 recipe：基座模型已具备通用操作能力，下游微调只需少量数据即可见效。
> 来源：论文 Figure 11，第 11 页，<https://arxiv.org/abs/2410.24164>

### 5.2 零样本跨 embodiment

π0 最核心的卖点是**一个模型控制多种本体**。在预训练覆盖的 7 种本体上，同一份 π0 权重无需任何针对性调整即可执行任务——从单臂 UR5e 的桌面清理，到双臂 ARX/Trossen 的折叠，再到移动底座的移动操作。这个能力来自第 3.5 节的"语义层共享、动作层本体化"设计：VLM 骨干学到了与本体无关的任务语义，动作专家再按本体输出对应维度的连续动作。

### 5.3 微调结果

在语言指令跟随实验中，微调后的 π0 与最强基线 π0-small 对比，进一步量化了 VLM 预训练对"听懂语言"的增益。在更复杂的后训练任务（洗衣折叠、清理餐桌、组装纸盒等）上，π0 展现了处理**多阶段、时间上延展**任务的能力——例如洗衣折叠需要"从烘干机取衣 → 装进篮子 → 搬到折叠台 → 逐件折叠"，这类任务要求模型具备长程规划与对视觉扰动的鲁棒性，π0 通过预训练 + 微调的 recipe 做到了。

### 5.4 消融与失败案例

- **VLM 预训练消融（π0-small）**：去掉 VLM 初始化后性能大幅下滑，是论文最重要的消融，直接支撑"VLM 骨干 + 连续动作"的设计正确性；
- **架构容量对比（Octo）**：支持 chunk 但容量不足的 Octo 落后，说明"大而强"的架构与"连续分布建模"缺一不可；
- **失败案例**：论文主要在难任务（Bussing Hard、复杂的多阶段装配）上暴露出性能衰减，长程任务中的视觉扰动与重试策略仍是难点；但论文未像 VPP 那样单列每个失败 case 的定量统计，失败分析偏定性。

## 6. 与相关工作的关系

- **vs RT-2 / OpenVLA（离散 token VLA）**：同属"VLM 迁移到动作"的大路线，但动作表示截然不同。RT-2 / OpenVLA 把动作量化成离散 token 自回归生成，π0 用 flow matching 生成连续流。π0 的实证结论是：高频灵巧操控场景下，连续流明显优于离散 token，因为离散化破坏连续性、且自回归不支持 action chunk；
- **vs Diffusion Policy / Octo（连续扩散策略）**：同属连续动作建模，但缺少 VLM 预训练。π0 通过 PaliGemma 骨干引入了 Internet 级语义知识，从而获得跨任务、跨本体泛化，这是纯扩散策略难以企及的；
- **vs 世界模型路线（UniPi、SuSIE、VPP）**：世界模型路线先"预测未来"再"反推动作"，π0 不做显式未来预测，而是把动作建模直接接在 VLM 语义表征上，训练与推理更简洁，代价是少了世界模型的物理先验；
- **系列内沿革**：π0 是 Physical Intelligence 通用机器人基础模型的起点。此后的演进不是简单堆数据：π0-FAST 解决自回归动作表示的训练效率，π0.5 解决异构知识迁移与开放世界泛化，π0.5+KI 解决连续动作专家破坏 VLM 知识的问题，π*0.6 用 Recap 引入部署经验与强化学习，π0.7 再把多源数据统一成可操控的条件行为模型（详见第 9 节）。

## 7. 局限与批判性评价

1. **VLM 骨干偏小（3B）**：相比同期 7B / 13B 的 VLA（如 OpenVLA-7B），π0 的 PaliGemma-3B 语义容量有限，可能限制了它在更复杂语言推理、更细粒度指令跟随上的上限——这也是 π0.7 扩到 4B 骨干 + MEM 视频历史的动因；
2. **数据成本高**：约 10,000 小时的数据，其中大量来自专家遥操作，采集成本与标注成本极高，难以被学术界和中小团队复现；
3. **"本体归一化"掩盖了动作空间的根本难题**：π0 靠"语义共享、动作本体化"实现跨本体，但动作空间归一化本身需要为每个本体设计映射，扩展到全新本体（训练中完全没见过的新形态）时的泛化并未在论文中充分验证；
4. **缺世界模型、缺显式未来建模**：π0 是纯反应式的条件动作模型，没有显式的未来预测或物理推演，面对需要长程规划、多步推理、物体间物理交互的任务时，其上限受限——这正是 π0.7 引入 BAGEL 世界模型 subgoal 的补位点；
5. **评测以归一化分数为主**：不同任务的打分细则（Appendix E）差异较大，归一化分数聚合后可能掩盖个别任务上的显著失败；失败案例分析偏定性，缺乏系统性的错误归因；
6. **论文对 π0 初代的数据构成交代有限**：专家遥操作与自主数据的精确比例、开源数据的具体清单与配比在正文中着墨不多，复现时难以精确对齐数据分布。

## 8. 复现与实践建议

- **算力门槛**：π0 全量预训练 700k steps，VLM 骨干 3B + 动作专家，需要大规模多卡训练集群，个人与小团队几乎无法从头复现；但 openpi 官方库支持在预训练权重上做下游微调，微调对算力要求相对友好；
- **代码可获得性**：`github.com/Physical-Intelligence/openpi` 已开源，含模型定义、训练与推理脚本，是当前最完整、最活跃的 flow matching VLA 参考实现之一；
- **数据准备**：跨本体数据的关键在动作空间归一化——需要为每个本体定义统一的状态/动作接口；视觉侧保证每本体 1–3 个相机视角的一致性；
- **实现要点**：
  - VLM 骨干冻结还是微调需权衡：π0 联合训练骨干与动作专家，但微调时可冻结骨干只训动作专家以省显存；
  - action chunk 长度默认 $H=50$；控制频率是数据/机器人接口属性，应分别调节 horizon、重规划间隔与执行频率，不要把三者绑定成固定 50 Hz；
  - flow matching 的 ODE 积分步数是推理延迟与精度的关键旋钮，需在目标硬件上实测取舍；
- **常见踩坑**：离散 token VLA 的经验不能直接照搬——动作连续化后，损失尺度、归一化、以及 flow 时间步采样分布都需要重调；另外多本体联合训练时各本体数据占比若不均衡，会导致模型偏向数据多的本体。

## 9. PI 系列演进：从动作生成到可操控的通用机器人基础模型

### 9.1 先给结论：它不是一条单纯的“换大骨干”路线

PI 系列真正的演进主轴可以压缩成六次瓶颈转移：

1. **π0：动作怎么生成？** 用 flow matching action expert 取代逐维离散动作 token，解决高频、连续、灵巧控制。
2. **π0-FAST / π0.5+KI：动作知识怎么高效学进 VLM，又不破坏 VLM？** FAST 改进离散动作表示，Knowledge Insulation 隔离连续动作梯度。
3. **Hi Robot / π0.5：机器人怎么走出实验室？** 引入高层语言子任务、Web 数据、多环境与跨本体数据，解决长程任务与开放世界泛化。
4. **RTC / π0.6 / π*0.6：模型能做之后，怎样跑得实时、稳定、可靠？** RTC 吸收推理延迟；Recap 让策略从失败、纠正和自主实践中改进。
5. **MEM / human-to-robot transfer：数据和上下文还能怎样扩展？** 用视频与文本记忆覆盖分钟级历史，并把人类视频变成新的技能来源。
6. **π0.7：怎样把所有异质数据合进一个模型而不“平均成平庸策略”？** 用详细语言、质量/速度/错误元数据、控制模式与视觉子目标，把行为差异显式条件化，获得可操控和组合泛化。

所以，PI 的路线并不是“π0 之后继续堆机器人数据”，而是不断重写三个接口：**动作接口、数据接口、推理/部署接口**。

### 9.2 时间线与每一代解决的问题

| 时间 | 工作 | 核心变化 | 解决的瓶颈 | 新暴露的问题 |
|---|---|---|---|---|
| 2024-10 | π0 | PaliGemma 3B + 300M flow action expert；50 步连续动作块 | 离散动作难以支持高频灵巧控制 | 连续动作损失训练慢，也可能干扰 VLM 表征 |
| 2025-01 | FAST / π0-FAST | DCT + 量化 + BPE，把动作块压成高信息密度 token | 自回归 VLA 的动作 token 冗余；训练 GPU 小时最高减少约 5× | 自回归推理约 750 ms/chunk，反而慢于 π0 的约 100 ms |
| 2025-02 | Hi Robot | 高层 VLM 解释复杂指令与用户反馈，低层 π0 执行动作 | 平坦 VLA 难以处理开放式、多阶段指令 | 高低层分离，语言接口存在信息瓶颈 |
| 2025-04 | π0.5 | 异构 co-training；高层子任务预测；FAST 预训练 + flow 后训练 | 未见住宅、未见物体与长程家务的开放世界泛化 | 两阶段训练复杂；连续专家仍可能损伤 VLM 知识 |
| 2025-05 | π0.5 + KI | FAST/VLM 目标更新主干，flow expert 对主干 stop-gradient | 同时获得快训练、快推理、语言跟随与知识迁移 | 训练期需维护离散/连续两套动作表示 |
| 2025-06 | RTC | 异步生成下一动作块，并对已承诺动作做 flow inpainting | 大 VLA 推理延迟导致停顿和 chunk 边界跳变 | 推理期 guidance 有额外计算；后续转向 training-time RTC |
| 2025-11 | π0.6 / π*0.6 | 约 5B 主体；Recap 用 advantage conditioning 做 offline RL + 部署后迭代 | 纯模仿学习的误差累积、低成功率与低吞吐 | 仍需成功标签、人工纠正和分批重训 |
| 2026-03 | π0.6-MEM | 视频短期记忆 + 文本长期记忆 | 遮挡、失败重试、分钟级多阶段任务 | 仍是单 episode 记忆，文本摘要可能丢细节 |
| 2026-04 | π0.7 | diverse context conditioning；自治/失败/人类视频/网络数据统一训练 | 组合泛化、跨本体迁移、开箱即用专家性能 | 未见任务成功率仍约 60%–80%，复杂长程任务仍需 coaching |
| 2026-10 | Pi API beta | 上传数据、托管微调、云端推理 | 把模型从研究原型变为可迭代的平台能力 | 不是新模型代号；网络延迟、封闭权重与独立复现仍是问题 |

### 9.3 π0：先把“动作”从语言 token 中解放出来

π0 的基础结构是一个约 **3.3B** 的模型：PaliGemma 3B 负责图像和语言表征，约 300M 的 action expert 负责连续动作生成。输入为 2–3 路 RGB、语言指令和本体状态；输出是长度 $H=50$ 的连续动作块。训练时通过 conditional flow matching 学习从高斯噪声到真实动作块的速度场，推理用约 10 次 Euler 积分生成动作。

这一代的决定性贡献不是“模型更大”，而是建立了**VLM 语义主干 + 连续 motor expert**的分工：前者继承互联网视觉语言知识，后者专门处理高频、精确、多模态的连续控制。约 10,000 小时、903M 自有时间步、7 类机器人配置和 68 个任务证明了这套结构可以做跨任务、跨本体预训练。

它的局限也很明确：action expert 从随机初始化开始，连续 flow loss 会通过联合训练影响主干；训练收敛慢，语言跟随可能被强视觉—动作相关性淹没。后续 FAST 与 KI 都是在修这个问题。

### 9.4 π0-FAST：解决的是训练效率，不是推理加速

π0-FAST 最容易被误解。它不是视觉 token 剪枝，也不是 π0 的“快速推理版”；它把连续动作块编码成适合自回归 Transformer 学习的离散序列：

1. 每个动作维度按 1%/99% 分位数归一化；
2. 沿时间轴做 DCT，把平滑轨迹的能量集中到低频；
3. 缩放并取整，让无关高频系数变成零；
4. 按“频率优先”展开，使模型先预测轨迹整体形状、再补细节；
5. 用 BPE 压缩重复零值和常见系数组合。

50 Hz、14 维双臂动作的一秒序列，朴素方法需要 700 个 token，FAST 平均约 53 个。FAST+ 又用 100 万条真实机器人动作轨迹训练成通用 tokenizer。最终 π0-FAST 在约 10,000 小时数据上能匹配 flow-based π0，并把训练 GPU 小时降低约 5×。

![](assets/π0%20-%20视觉语言动作流模型与系列演进/figures/04-fast-teaser.png)

> **图 4：FAST 将高频动作先变换到频域，再压缩成高信息密度 token。** 控制频率越高，逐时间步分箱越容易退化为复制上一动作；FAST 则保持较稳定的策略质量。  
> 来源：FAST 论文 Figure 1，<https://arxiv.org/abs/2501.09747>

关键代价是：**训练快，推理慢**。π0-FAST 生成一秒动作块约需 750 ms，而 π0 的小 action expert 做 10 次 flow 迭代约需 100 ms。这个矛盾直接引出 π0.5/KI 的混合路线：用 FAST 教主干学动作表征，但部署时仍让 flow expert 输出连续动作。

### 9.5 Hi Robot 与 π0.5：从“能做动作”转向“能在陌生环境做长任务”

Hi Robot 先把 π0 变成分层系统：高层 VLM 处理“做一个不加番茄的素食三明治”或“那不是垃圾”这类复杂指令与反馈，输出短而明确的子任务；低层 π0 再执行“拿起全麦面包”之类原子动作。它证明了高层语义推理与低层控制分离的价值，也为 π0.5 的显式子任务预测铺路。

π0.5 的重点是**异构知识迁移**。它不是简单增加自主数据，而是把多种监督统一到同一个 Transformer：

- 约 400 小时目标移动操作数据，覆盖约 100 个住宅环境；
- 其他固定单/双臂机器人在更多住宅中的数据；
- 实验室跨本体数据和 OXE；
- Web 图像描述、VQA、目标定位；
- 人工标注的高层子任务和目标框；
- 后训练阶段的人类 verbal instruction。

其预训练样本中约 **97.6% 并非目标移动机器人家务数据**。这正是论文的核心：开放世界泛化不是靠把目标机器人数据堆满，而是让 Web 语义、其他机器人技能和多环境经验迁移到目标平台。

训练上，π0.5 先用 FAST 离散动作做 280k 步预训练，再加入 flow action expert 做 80k 步后训练。推理时，同一个模型先预测高层语言子任务 $\hat{\ell}$，再以该子任务为条件生成低层连续动作。它由此能在完全未见的厨房和卧室中执行 2–15 分钟的清理任务。

![](assets/π0%20-%20视觉语言动作流模型与系列演进/figures/05-pi05-data-recipe.png)

> **图 5：π0.5 在未见厨房中将总体任务分解为关柜门、物品入抽屉、擦拭洒落物、餐具入水槽等子任务。** 这体现了“高层语义预测 + 低层连续控制”的统一层级结构。  
> 来源：π0.5 论文 Figure 2，<https://arxiv.org/abs/2504.16054>

消融结果说明：ME 多环境数据、CE 跨本体数据、Web 数据和高层监督各自解决不同问题。Web 数据主要提升 OOD 物体理解和高层决策；ME/CE 对实际动作泛化更关键；只用 GPT-4 做零样本高层规划反而最差，因为它不了解低层策略真正会什么。

### 9.6 Knowledge Insulation：PI 系列真正稳定下来的训练配方

π0.5 的两阶段方案揭示了一个更深的问题：如果让随机初始化的连续 action expert 把 flow 梯度直接传回 VLM，主干会出现不利学习动力学，训练变慢，并遗忘原有语言和 Web 知识；但若完全冻结主干，原始 VLM 表征又不够适合机器人控制。

Knowledge Insulation 的解法是“**让表征适配，但隔离有害梯度**”：

- VLM 主干由普通 VLM 数据、robot planning 文本和 FAST 动作 token 的交叉熵更新；
- action expert 可以读取主干的 K/V 表征；
- flow loss 到主干的路径 stop-gradient，只更新 action expert；
- 推理时丢弃 FAST 自回归路径，只用小 action expert 输出连续动作。

这样同时保留了 π0-FAST 的快速收敛、π0 的低延迟连续控制和 VLM 的语义泛化。代价是单步训练计算约增加 20%，且训练管线必须维护离散/连续两套动作目标。KI 后来成为 π0.6、π0.7 的基础训练思想。

### 9.7 RTC：把“模型很慢”改写成一个异步控制问题

动作块并没有消灭延迟：大模型生成下一 chunk 时，机器人要么停下来等，要么无约束切换到新 chunk，造成位置、速度和策略模式跳变。RTC 在机器人执行当前 chunk 时异步生成下一 chunk，并把推理期间已经承诺要执行的动作当作新 chunk 的冻结前缀；其余部分通过 flow inpainting 生成。

RTC 不改模型权重，也不需要重训。真实机器人实验表明，它在额外 100/200 ms 延迟下仍保持较好吞吐，并能在总延迟超过 300 ms 时执行点火等精细任务。后续 training-time RTC 把前缀条件训练进模型，移除了推理时 guidance 的额外反向计算；π0.7 明确采用了这一路线，在训练中模拟 0–12 个控制步的延迟。

### 9.8 π0.6 与 π*0.6：从 imitation 进入 experience + correction + RL

π0.6 是 π0.5 之后的监督学习基座：Gemma 3 4B VLM（含约 400M 视觉编码器）+ 860M flow action expert，总体约 5B；继续采用 FAST 与连续动作双表示、Knowledge Insulation、高层子任务和更丰富的元数据条件。

π*0.6 的星号表示它不是普通 SFT 模型，而是通过 **Recap** 学习经验后的版本。Recap 的核心是给策略增加一个二值优势条件：`Advantage: positive/negative`。训练流程是：

1. 在多任务、多机器人数据上训练 distributional value function；
2. 根据回报和 value 估计动作 advantage，并按任务阈值二值化；
3. 预训练同时学习无条件行为分布与 advantage-conditioned 行为分布；
4. 对具体任务先用示范 SFT；
5. 部署收集自主 rollouts、成功/失败标签和人工 intervention；
6. 分批重训 value 与策略，再次部署。

![](assets/π0%20-%20视觉语言动作流模型与系列演进/figures/06-pistar06-recap.png)

> **图 6：π*0.6 的 advantage-conditioned VLA 与 value function。** 价值模型把部署数据转成优势标签，VLA 在相同的离散/连续动作双路径上学习“哪些动作比行为策略更好”。  
> 来源：π*0.6 / Recap 论文模型图，<https://arxiv.org/abs/2511.14759>

Recap 在咖啡、洗衣和纸箱组装等任务上把最难任务的吞吐量提高到 2× 以上，失败率大约减半；但它仍不是全自动在线 RL：奖励标签、人工纠正和环境 reset 仍需人参与，策略也是“分批收集—offline 更新—再部署”。

### 9.9 两条能力支线：MEM、human-to-robot transfer 与 RL Token

#### 9.9.1 MEM：长短期记忆分工

π0.6-MEM 把机器人历史拆成两种表示：短期使用带因果时间注意力的视频编码器，保存遮挡、动力学和最近失败；长期使用递归更新的文本摘要，记录“哪些步骤已完成”。短期窗口预训练约 5 秒，后训练可扩到 54 秒；长期任务展示达到约 15 分钟。

π0.7 继承的是 MEM 的视频历史编码和连续状态 token，而不是简单把整个 π0.6-MEM 高低层系统原样复制。它每路相机最多输入 6 帧历史，并把视频记忆纳入统一多模态 prompt。

#### 9.9.2 人类视频迁移：数据扩展开始出现“涌现阈值”

PI 的 human-to-robot 工作把人类视频当作一种新 embodiment：用 3D hand track 预测低层末端轨迹，用密集语言标注预测高层子任务。关键结论是，只有当机器人预训练覆盖足够多任务、场景和本体后，人类与机器人 latent 才自然对齐；此时加入人类视频，才能把只在人类数据中出现的泛化设置性能提升到近 2×。π0.7 随后把第一视角人类视频正式纳入更大的数据混合。

#### 9.9.3 RL Token：精密任务的轻量快速后训练

Recap 直接训练大型 advantage-conditioned VLA，适合从大规模部署经验中改进通用策略；RL Token 则是另一条更轻的任务专精路线：从冻结 VLA 内部抽取一个紧凑表示，训练小型 actor-critic 头，并用正则约束 actor 不要偏离 VLA 建议。它在螺丝、扎带、充电器和网线插入上，用几分钟到几小时真机练习把关键阶段加速最多 3×。因此 RLT 是**精密操作后训练支线**，不是 π0.7 的代号或主体架构。

### 9.10 π0.7：把“混合数据”升级为“条件化行为建模”

π0.7 仍是约 5B：Gemma 3 4B VLM + 860M action expert，并延续 Knowledge Insulation、flow matching、视频历史和 training-time RTC。真正的变化在 prompt：

$$\mathcal C_t=\{\ell,\hat\ell_t,\mathbf g^\star,m,c\}$$

其中 $\ell$ 是总体任务，$\hat\ell_t$ 是当前子任务，$\mathbf g^\star$ 是视觉子目标，$m$ 是速度/质量/错误元数据，$c$ 是 `joint` 或 `ee` 控制模式。

这组条件解决了“数据越多，策略可能越平庸”的问题。示范、自主轨迹、RL 专家轨迹和失败数据的质量、速度、策略都不同；如果直接行为克隆，模型会把这些模式平均起来。π0.7 用元数据显式解释差异，训练时可以放心加入低质量甚至失败数据，推理时再条件到“高质量、快速、无错误”。

视觉子目标由独立 world model 根据当前观察、子任务和元数据生成，表达“下一阶段成功后应该长什么样”。需要注意两点：

- 这个 world model 初始化自 BAGEL 14B，但**不包含在约 5B 的 VLA 参数量中**；
- π0.7 的高层语义策略、world model 和低层 VLA 是异步协同组件，不应被误解成一个完全单体的 5B 模型。

![](assets/π0%20-%20视觉语言动作流模型与系列演进/figures/07-pi07-overview.png)

> **图 7：π0.7 的训练与推理总览。** 训练混合示范、自主机器人数据、Web 多模态数据和第一视角人类视频，并用语言、视觉子目标和 episode metadata 描述行为；推理时由高层策略、world model 和目标元数据共同调节低层 VLA。  
> 来源：π0.7 论文 Figure 1，<https://arxiv.org/abs/2604.15483>

π0.7 的代表性结果包括：在未见过衣物折叠数据的双臂 UR5e 上，T 恤折叠成功率 80.0%，接近资深遥操作员首次尝试的 80.6%；无需任务微调即可在 espresso、洗衣和纸箱组装上接近 π*0.6 专家。它也能重组技能完成训练中没有作为完整任务出现的空气炸锅、法压壶等操作。

但“emergent”需要克制理解：这些能力更像是**从大规模数据中重组已有子技能**，不是凭空发明动作。论文也明确指出，分布内任务经常超过 90%，未见任务或未见任务—本体组合通常仍在 60%–80%；复杂长程新任务仍需要人类逐步 language coaching。

### 9.11 开源状态与 2026 年 10 月的产品化位置

截至 2026-10-20：

- openpi 开源并提供基础权重：**π0、π0-FAST、π0.5**；三者均在 10,000+ 小时机器人数据上预训练；
- **π0.6、π*0.6、π0.6-MEM、π0.7** 没有公开权重；
- Pi API beta 于 2026-10-13 开放申请，提供“上传数据 → 托管微调 → 云端推理”的闭环；官方只称使用“latest models”，没有发布 π0.8 等新代号。因此 API beta 应视为**部署方式的演进**，不是新的模型世代。

### 9.12 个人判断：PI 路线真正形成的三个范式

1. **动作表示不是二选一，而是训练/推理解耦。** FAST 离散 token 很适合给 VLM 主干提供稳定学习信号，flow expert 很适合部署时输出连续动作；KI 把二者组合成了稳定 recipe。
2. **泛化的关键从“模型容量”转向“给数据消歧”。** π0.7 最重要的不是 5B 参数，而是让任务、策略、质量、速度和目标状态都成为条件，使低质量与失败数据也能扩大状态覆盖。
3. **后训练会成为真实机器人性能的决定因素。** π0 解决基座能力，Recap/RLT 解决可靠性与最后毫米；这类似 LLM 从预训练走向 SFT/RL，但机器人还多了物理交互引起的分布漂移和数据成本。
4. **π0.7 还不是产品级通用机器人。** 60%–80% 的未见组合成功率对论文很强，对无人值守部署仍不够；复杂长程任务依赖高层策略、world model、语言 coaching 和人工数据管线，系统复杂度并未消失，只是从手工技能工程转移到了数据与模型编排。
