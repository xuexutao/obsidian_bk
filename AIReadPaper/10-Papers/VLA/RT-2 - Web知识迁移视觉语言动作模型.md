# RT-2：Web 知识迁移视觉语言动作模型

## 基本信息

- **作者**：Anthony Brohan、Noah Brown、Justice Carbajal、Yevgen Chebotar、Xi Chen、Krzysztof Choromanski、Tianli Ding、Danny Driess、Chelsea Finn、Karol Hausman、Sergey Levine、Tianhe Yu、Brianna Zitkovich 等
- **机构**：Google DeepMind
- **发表**：arXiv 2307.15818，CoRL 2023
- **论文原题**：*RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control*
- **项目页**：<https://robotics-transformer2.github.io/>
- **核心前作**：[[RT-1 - 大规模真实机器人控制的Robotics Transformer]]
- **本地材料**：`assets/RT-2 - Web知识迁移视觉语言动作模型/sources/paper.pdf`

## 一句话结论

RT-2 把连续机器人动作离散为 256 档并直接复用 VLM 的文本 token 输出空间，在 PaLI-X 5B/55B 与 PaLM-E 12B 上将互联网视觉语言数据和 RT-1 机器人轨迹共同微调，使同一个模型端到端完成“图像 + 指令 → 低层动作”；它没有凭 Web 数据学会新运动，却把符号理解、语义推理、多语言和人物识别迁移到控制中，在未见对象/背景/环境上的平均成功率达到 62%，约为 RT-1 的 32% 的两倍，首次把“VLA”从概念变成了可量化的真机范式。

## 1. 研究背景与问题定义

### 1.1 从 RT-1 的机器人专用 Transformer 到互联网预训练 VLM

RT-1 已证明，只要真实机器人数据足够多样，35M 参数的 Transformer 就能在 700 余种语言指令之间共享视觉与动作规律。然而它的语义知识主要来自机器人演示：训练数据没有出现某个图标、数字、人物属性或物体类别时，策略很难仅靠 USE 句向量和 ImageNet 特征理解它。扩大机器人数据当然可行，但互联网 VLM 预训练使用的是十亿级图文样本，真实机器人轨迹在可预见时间里不可能达到同一规模。

RT-2 提出的核心问题因此不是“怎样把 LLM 当规划器”，而是更激进的：**能否让已经掌握开放世界视觉语义的 VLM 直接输出笛卡尔低层控制，并让 Web 知识在端到端训练中真正进入动作决策？** 这与 SayCan、PaLM-E 高层规划的差异在于，后者往往把大模型放在状态机或任务分解层，动作仍由独立技能执行；RT-2 则要求 VLM 的共享参数同时承担视觉理解、语言推理和动作生成。

### 1.2 关键矛盾

这一目标包含三个工程矛盾。第一，VLM 输出文本，而机器人需要 6-DoF 位姿增量、夹爪和终止信号；必须建立统一输出空间。第二，只在机器人数据上微调容易灾难性遗忘 Web 语义，但只保留 Web 目标又可能稀释稀缺的动作监督。第三，55B 模型远超机载算力，却要在闭环中达到 1–3 Hz，并且所有输出都必须是可执行动作而不是自由文本。

### 1.3 核心贡献

1. 定义 **Vision-Language-Action（VLA）** 配方：把动作表示成现有 tokenizer 中的文本 token，不增加动作专用模块；
2. 在 PaLI-X 5B/55B 和 PaLM-E 12B 上联合训练 Web 视觉语言任务与机器人行为克隆；
3. 通过约 6000 条真机评测证明，Web 预训练主要迁移语义与视觉组合能力，而非新运动技能；
4. 系统消融模型规模、从零训练、仅机器人微调和共同微调；
5. 用“Plan + Action”输出初步展示单一 VLA 中的链式语义推理与低层动作衔接。

## 2. 任务定义与输入输出

### 2.1 输入、输出与闭环假设

每个控制步输入当前机器人相机图像和自然语言任务，标准提示形如：

> `Q: What action should the robot take to [task instruction]? A:`

输出是 8 个离散整数：终止标记、末端执行器三维位置增量、三维旋转增量和夹爪开度。除终止标记外，连续维度各均匀量化到 256 个 bin。论文正文给出的顺序是：

$$a_t=(e_t,\Delta x_t,\Delta y_t,\Delta z_t,\Delta r^x_t,\Delta r^y_t,\Delta r^z_t,g_t)$$

对应文本串例如 `1 128 91 241 5 101 127`。模型每次收到新图像重新预测，动作反量化后执行，因此仍是视觉反馈闭环，而不是一次性生成完整轨迹。

RT-2 沿用 RT-1 的 7-DoF 移动机械臂和厨房操控数据。它默认相机图像已经可观察任务所需状态，并假定动作空间与训练本体一致；论文不解决跨本体坐标映射，也不通过 Web 数据学习接触动力学。

### 2.2 统一 token 空间

PaLI-X 的 tokenizer 对 0–1000 的整数有独立 token，故可直接令 0–255 对应动作 bin。PaLM-E 没有同样便利的整数表示，作者覆盖其 256 个最低频 token 作为动作词表。这是一种 symbol tuning：token 的表面符号并不重要，只要训练建立稳定的“符号—动作”对应关系。

机器人任务推理时使用**约束解码**，只允许合法动作 token；普通 VQA 或描述任务仍允许完整自然语言词表。这一边界约束很关键：共享输出头带来参数复用，但若不约束，哪怕极低概率的自然语言 token 也可能造成控制接口失效。

### 2.3 优化目标

所有任务都转成自回归 next-token prediction。对机器人样本，这等价于离散行为克隆：

$$\mathcal L_{\mathrm{robot}}=-\sum_{t}\sum_{j=1}^{8}\log p_\theta(a_{t,j}\mid I_t,g,a_{t,<j})$$

共同微调时再加 VQA、图像描述和交错图文任务：

$$\mathcal L=\lambda_r\mathbb E_{D_r}[\mathcal L_{\mathrm{robot}}]+\lambda_w\mathbb E_{D_w}[\mathcal L_{\mathrm{VLM}}]$$

论文实现不是显式报告固定损失系数，而是通过 batch 采样权重控制混合比例：PaLI-X 训练中机器人数据约占 50%，PaLM-E 中约占 66%。共同微调的直觉不是让 Web 样本直接提供动作标签，而是在动作学习期间持续“复习”开放世界语义，避免机器人小域把预训练知识冲掉。

## 3. 核心方法

### 3.1 总体架构：动作就是另一种语言

![](assets/RT-2%20-%20Web知识迁移视觉语言动作模型/figures/01-overview.png)

> **图 1：RT-2 总体流程。** Web VQA 和机器人动作样本被统一成图像—提示—文本 token 序列，共同微调 VLM；部署时动作 token 被反量化成低层控制并闭环执行。图中最重要的不是某个新模块，而是模型参数和输出词表在语言任务与动作任务之间完全共享。来源：论文 Figure 1，第 2 页，arXiv:2307.15818。

RT-2 没有为机器人另造一个大规模骨干，而是把两个现成 VLM 族转成 VLA：

- **RT-2-PaLI-X**：视觉侧为 ViT，语言侧为 UL2 风格 encoder-decoder；实验规模为 5B 和 55B。55B 版本包含约 22B 的 ViT 与约 32B、50 层的编码解码骨干；
- **RT-2-PaLM-E**：以 decoder-only PaLM-E 为主，图像经 ViT-4B 投影到语言嵌入空间，实验规模 12B；
- **Language-Table 变体**：PaLI 3B，用 ViT-G/14 与 UL2-3B，在不同机器人、二维动作仿真上验证配方可迁移。

从建模角度，RT-2 将策略写成统一条件生成模型：

$$p_\theta(y\mid I,q),\qquad y\in \mathcal V_{\mathrm{text}}\cup\mathcal V_{\mathrm{action}}$$

当 $q$ 是 VQA 提示时 $y$ 是自然语言；当 $q$ 是控制提示时，约束 $y\in\mathcal V_{\mathrm{action}}$。因此所谓“VLA”并不是把三个网络串联，而是同一个自回归模型在上下文中选择输出语义。

### 3.2 机器人动作数据如何进入 VLM

每条机器人轨迹拆成逐时刻样本：相机图像、任务文本和示范动作。连续动作按 RT-1 量化，8 个维度按固定次序拼成空格分隔字符串。这样可以直接使用 VLM 已有的数据管道、交叉熵、teacher forcing 与解码器，而无须新增回归头。

这种设计有三项影响。其一，动作维之间变成自回归依赖，而非 RT-1 式并行分类，后一个动作维可条件于前一维。其二，语言和动作共享 embedding/softmax 参数，Web 预训练得到的表征可直接影响动作概率。其三，动作精度仍受 256-bin 量化限制，且整数 token 本身没有物理几何结构，相邻 bin 在词表空间未必相邻。

### 3.3 共同微调而非朴素微调

RT-2 最关键的训练选择是 **co-fine-tuning**。朴素 fine-tuning 只用机器人样本，虽然能学会控制，却会削弱符号、类别和关系知识。共同微调在每个训练阶段混入原 VLM 任务，使视觉语义与动作接地同步发生。论文的消融清楚表明：5B 从零训练在未见设置平均仅 9%，预训练后仅机器人微调为 42%，共同微调为 44%；55B 则由仅微调的 52% 提升到共同微调的 63%。收益在大模型上更明显，说明规模扩大只有在保留预训练知识时才真正转化为泛化。

数据来源方面，Web 侧主要沿用 PaLI-X/PaLM-E 原始混合，其中 WebLI 含约 100 亿图文对，经过跨模态相似度筛选保留前 10%，形成约 10 亿训练例，并混合图像描述、VQA 与交错图文任务。机器人侧来自 RT-1：13 台机器人、17 个月采集的真实厨房演示，覆盖 pick、move-near、upright、knock、open/close drawer、place-into 与从容器取出等动作族。

### 3.4 训练规模与超参数

- PaLI-X 55B：学习率 $10^{-3}$、batch 2048、80k steps；
- PaLI-X 5B：学习率 $10^{-3}$、batch 2048、270k steps；
- PaLM-E 12B：学习率 $4\times10^{-4}$、batch 512、1M steps；
- PaLI 3B Language-Table：学习率 $10^{-3}$、batch 128、300k steps。

论文沿用原 VLM 学习率调度和正则。训练成本没有给出 TPU 芯片数或总 FLOPs，因此只能判断为“大型工业研究级”：55B 模型、2048 batch 和原始 Web 混合意味着复现实验的主要门槛远高于机器人数据本身。

### 3.5 实时推理与部署

55B VLA 无法在常规机器人 GPU 上运行。作者把模型部署为多 TPU 云服务，机器人通过网络查询；PaLI-X 55B 达到 1–3 Hz，5B 约 5 Hz，并可由同一服务支持多台机器人。这个设计使大模型真机闭环成为可能，但把网络延迟、服务可用性和云算力纳入控制系统。与 RT-1 的本地 3 Hz 相比，RT-2 的“实时”是高成本远程实时，不是边缘部署。

### 3.6 Chain-of-Thought 变体

作者在 PaLM-E 版本上额外微调数百步，把目标改成 `Plan: ... Action: ...`。自然语言计划先解释要操作的对象，再输出动作。例如“我需要锤钉子”先回答“rock”，随后给出抓取动作。这在架构上把高层语义规划和低层控制放进一次自回归生成，但论文只给定性案例，没有严格对照、成功率和长程闭环评测，不能将其视为成熟的分层规划方案。

## 4. 数据集与实验设置

### 4.1 真机评测轴

约 6000 条评测轨迹分为：

1. **Seen tasks**：200 多条训练任务，仍随机化物体位置、时间与机器人位置；
2. **Unseen objects**：新类别和难抓玩具；
3. **Unseen backgrounds**：新桌布、干扰物和视觉背景；
4. **Unseen environments**：厨房水槽与更困难的办公室桌面；
5. **Emergent evaluations**：训练机器人数据从未出现的符号、数学、Logo、营养、多语言与人物属性指令。

未见对象/背景/环境共有 280 多项任务，并区分 easy/hard。涌现能力采用 A/B 评测，四个模型在完全相同场景顺序执行，每条指令运行 5 次，降低现场变化带来的方差。

### 4.2 Baseline

- **RT-1 35M**：同一机器人数据、无 Web VLM 预训练；
- **VC-1**：机器人视觉预训练 ViT-L + USE 指令 + TokenLearner + RT-1 解码器，端到端解冻；
- **R3M**：Ego4D 人类视频表征 ResNet50，后接同类语言条件控制头；
- **MOO**：VLM 只生成目标物体语义像素，再由 RT-1 控制，代表“VLM 作为外部感知模块”；
- **Language-Table 的 BC-Zero、RT-1、LAVA**：检验另一环境与二维动作空间。

所有主要 baseline 使用完全相同的机器人数据，因而 RT-2 与 RT-1 的差异可以较干净地归因于 VLM 预训练、容量与训练方案，而不是额外真机演示。

### 4.3 评价指标与统计边界

真机指标是任务成功率。论文报告的是聚合百分比，但多数场景单条指令仅 1–5 次，涌现评测每条 5 次，置信区间不充分。6000 次总量很大，却分散到众多模型与条件；因此 1–5 个百分点差异不应过度解读，真正稳健的是 2–3 倍量级的差距。

## 5. 实验结果与消融

### 5.1 主结果：未见分布泛化

![](assets/RT-2%20-%20Web知识迁移视觉语言动作模型/figures/02-generalization-results.png)

> **图 2：seen 与三类未见条件的成功率。** RT-2 在 seen 任务上与 RT-1 持平，但未见对象、背景、环境的优势显著，说明收益不是把原任务记得更牢，而是预训练概念迁移。来源：论文 Figure 4，第 8 页。

| 模型 | Seen | 未见对象 Easy/Hard | 未见背景 Easy/Hard | 未见环境 Easy/Hard | 未见平均 |
|---|---:|---:|---:|---:|---:|
| R3M | 45 | 32 / 14 | 13 / 9 | 0 / 2 | 12 |
| VC-1 | 63 | 34 / 10 | 13 / 3 | 0 / 0 | 10 |
| RT-1 | 92 | 31 / 43 | 71 / 9 | 26 / 14 | 32 |
| MOO | 75 | 58 / 48 | 38 / 41 | 19 / 3 | 35 |
| **RT-2 PaLI-X 55B** | **91** | **70 / 62** | **96 / 48** | **63 / 35** | **62** |
| **RT-2 PaLM-E 12B** | **93** | **84 / 76** | **75 / 71** | **36 / 33** | **62** |

两种 RT-2 的 unseen 平均都为 62%，约是 RT-1 32% 的 1.94 倍。PaLM-E 在困难对象/背景更强，PaLI-X 在容易背景与未见环境更强，暗示预训练数据配方影响具体能力结构，并非参数越多所有维度都单调领先。seen 上 91–93% 与 RT-1 的 92% 基本相同，说明巨大参数量没有牺牲原有控制能力，但也没有明显提高训练分布内上限。

### 5.2 跨平台 Language-Table

PaLI 3B 在 Language-Table 仿真达到 $90\pm10$，高于 LAVA 的 $77\pm4$、RT-1 的 $74\pm13$、BC-Zero 的 $72\pm3$。这里动作只有二维 $X,Y\in[-10,10]$，且共同训练还加入动作、指令、臂位置、帧间时间和成功预测五类任务。该结果支持“文本化动作”不是 Google Robot 专用技巧，但任务难度和动作空间远小于 7-DoF 真机，不能等价看待。

### 5.3 涌现语义能力

![](assets/RT-2%20-%20Web知识迁移视觉语言动作模型/figures/03-emergent-capabilities.png)

> **图 3：符号理解、推理和人物识别。** PaLI-X 55B 的平均成功率 60%，相对 RT-1 的 17% 超过三倍；PaLM-E 12B 在数学子集更有优势，体现预训练混合而非机器人演示决定语义能力。来源：论文 Figure 6a，第 10 页。

| 模型 | 符号理解均值 | 推理均值 | 人物识别均值 | 总平均 |
|---|---:|---:|---:|---:|
| VC-1 | 11 | 10 | 13 | 11 |
| RT-1 | 16 | 16 | 20 | 17 |
| **RT-2 PaLI-X 55B** | **82** | **46** | **53** | **60** |
| **RT-2 PaLM-E 12B** | **36** | **43** | **43** | **40** |

PaLI-X 的符号三组分别为 93/60/93；推理中数学 25、Logo 52、营养 48、颜色/多语言 58。PaLM-E 数学为 35，高于 PaLI-X 的 25，这与 PaLM-E 更强的语言/数学混合相符。需要强调，这些“涌现”是把已学会的 pick/move 技能接到新语义条件上，并不是从 Web 图文中发明新的闭环运动。

### 5.4 模型规模与训练策略消融

![](assets/RT-2%20-%20Web知识迁移视觉语言动作模型/figures/04-size-training-ablation.png)

> **图 4：参数规模与训练策略消融。** 从零训练 5B 几乎失败；VLM 预训练是决定性因素，共同微调又优于仅机器人微调，55B 对复杂泛化的收益明显。来源：论文 Figure 6b / Appendix Table 6。

| 规模与训练 | 未见对象 E/H | 未见背景 E/H | 未见环境 E/H | 平均 |
|---|---:|---:|---:|---:|
| 5B from scratch | 0 / 10 | 46 / 0 | 0 / 0 | 9 |
| 5B fine-tuning | 24 / 38 | 79 / 50 | 36 / 23 | 42 |
| 5B co-fine-tuning | 60 / 38 | 67 / 29 | 44 / 24 | 44 |
| 55B fine-tuning | 60 / 62 | 75 / 38 | 57 / 19 | 52 |
| **55B co-fine-tuning** | **70 / 62** | **96 / 48** | **63 / 35** | **63** |

最重要的消融不是 55B 比 5B 高，而是 from-scratch 5B 只有 9%。这排除了“纯容量吸收 130k 轨迹”即可得到开放世界泛化的解释。共同微调对 5B 只增加 2 点，却对 55B 增加 11 点，说明大模型更容易保留并利用 Web 知识，也可能更容易在机器人微调时产生知识漂移，需要原任务持续约束。

### 5.5 定性能力与失败案例

成功案例包括“把苹果移到数字 3”“把可乐推到心形图标”“把物体移到同色杯”“把可乐移到戴眼镜的人”“选健康饮料”等。CoT 变体还能选择石头当临时锤子、给疲惫的人选择能量饮料。

失败则集中在物理而非语义：Language-Table 中模型能找到正确笔或香蕉，却因滚动和质心不同而推落桌面；真机上难以按特定部位抓取、执行擦拭/工具使用、折毛巾等新运动、完成高精度灵巧动作，以及处理多层间接推理。由此可见，RT-2 的视觉语义覆盖远快于接触动力学和动作分布扩展。

## 6. 与 Google RT 系列的关系

### 6.1 相比 RT-1

RT-1 的贡献是高效机器人专用架构和规模化真实数据；RT-2 保留相同数据与离散动作思想，却把 EfficientNet+USE+小型 Transformer 替换为 Web 预训练 VLM，并将动作放入语言输出空间。RT-1 在 seen 任务已达 92–97%，RT-2 的必要性并非继续抬高 seen，而是把“概念组合泛化”扩展为互联网语义迁移。

### 6.2 对 RT-X、SARA-RT、AutoRT 与 RT-H 的铺垫

- [[RT-X - 跨本体机器人数据与模型]] 用 RT-1/RT-2 骨干吸收多本体数据，解决 RT-2 运动技能仍受单一机器人数据限制的问题；
- [[SARA-RT - 机器人Transformer线性注意力加速]] 直接对 PaLI-X 5B 的 ViT 注意力做 up-training，回应 RT-2 云端推理成本；
- [[AutoRT - 基础模型编排机器人数据收集]] 用 VLM/LLM 编排机器人在野外收集 77k 轨迹，试图扩展 RT-2 所缺的动作和场景覆盖；
- [[RT-H - 语言动作层级与干预学习]] 在 RT-2 之上增加语言动作中间层，改善多任务共享和人类纠错；
- [[RT-Trajectory - 轨迹草图条件任务泛化]] 则从条件表示入手，用轨迹草图弥补语言无法精确表达新运动的缺陷。

## 7. 局限与批判性评价

### 7.1 论文明确局限

1. Web 预训练不产生新运动技能，物理能力仍被机器人数据中的动作分布限制；
2. 55B 推理成本高，未来高频控制会被计算和网络延迟卡住，需要量化、蒸馏和更低成本硬件；
3. 可用于完整微调的高质量 VLM 当时很少，复现依赖未开放权重与内部数据；
4. 对新动力学、精确接触、折叠、擦拭、工具使用和多层推理仍薄弱。

### 7.2 批判性判断

“VLA”统一了接口，但未统一物理。动作 token 和文字 token 共享词表并不自动建立连续几何；真正的物理接地仍完全来自机器人轨迹。RT-2 的最大科学价值是用严格对照证明 Web 知识能够影响低层动作选择，而不是证明互联网数据能替代机器人数据。

其次，云端 55B 的 1–3 Hz 是一个昂贵的系统解，而非可普及部署方案。网络中断、尾延迟与数据传输安全都未进入论文评测。第三，评测中的人物与名人识别在当时用于展示语义迁移，但实际机器人产品需要更严格的隐私、公平性和误识别治理，成功率本身不足以证明可部署性。

## 8. 复现成本与实践建议

### 8.1 资源分级

- **完整复现**：极高。需要 PaLI-X/PaLM-E 级预训练权重、原始 Web 混合、大规模 TPU、RT-1 真实机器人数据和 7-DoF 真机；
- **训练配方复现**：高。可用开源 VLM 替代，保留动作文本化、约束解码和 Web/机器人共同微调；
- **小型验证**：中等。Language-Table 或公开 OXE 子集足以验证动作 token 化与 co-fine-tuning，不足以复现 55B 的涌现结果；
- **部署**：高。5B 仍需服务器级加速器；若要求本地高频控制，应考虑蒸馏、量化或动作分块。

### 8.2 最小复现清单

1. 明确定义每个动作维的范围、归一化和 256-bin 映射，并固定维度顺序；
2. 在 tokenizer 中预留 256 个单 token 符号，避免一个动作 bin 被拆成多个子词；
3. 控制任务使用合法动作词表约束解码；
4. 使用机器人样本过采样，而不是简单按原始数据量混合，否则十亿级 Web 数据会淹没动作监督；
5. 同时报告 seen、视觉 OOD、语义 OOD 和新动力学，避免把“识别对了”误写成“技能泛化”；
6. 评估端到端控制频率、尾延迟和失联降级策略，而不只报告模型 forward time。

## 9. 个人启发与后续问题

RT-2 最值得继承的是一种边界清晰的迁移观：Web 数据负责告诉机器人“世界里有什么、语言是什么意思、对象之间有什么关系”，机器人数据负责告诉模型“身体怎样动、接触会发生什么”。后续研究的关键不是继续混为一谈，而是让两类知识在更强的动作表示、世界模型和主动数据收集中互补。

可继续追问：动作 token 是否必须是无结构整数，还是应使用连续生成或具备几何邻域的编码？共同微调的最佳混合比例是否随模型规模和机器人数据多样性变化？语义推理先生成自然语言计划再行动，是否会引入不可验证的中间文本？怎样把 RT-X 的跨本体动作数据、AutoRT 的野外数据和 RT-H 的纠正信号统一到同一个可持续改进闭环？
