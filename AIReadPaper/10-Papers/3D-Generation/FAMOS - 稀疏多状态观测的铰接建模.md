# FAMOS：稀疏多状态观测的铰接建模

## 基本信息

- **论文全称**：FAMOS: Feed-Forward 3D Articulation Modeling from Sparse Observations
- **作者与机构**：Kevin Qu、Tao Sun、Massimiliano Viola、Liyuan Zhu、Zhizhuo Zhou、Sayan Deb Sarkar（Stanford）、Konrad Schindler（ETH）、Iro Armeni（Stanford）
- **arXiv**：[2609.20817](https://arxiv.org/abs/2609.20817)
- **项目页**：[kevinqu7.github.io/famos](https://kevinqu7.github.io/famos)（截至笔记撰写时未见开源代码）
- **一句话标签**：从一组稀疏、无序、部分重叠的局部点云（不同视角 + 不同铰接状态）中，一次前馈预测可动部件分割与关节参数；核心是「状态内 + 全局」交替注意力和「观测运动跨度」监督。

## 一句话结论

FAMOS 回答了一个 Particulate 没有回答的问题：**单靠一个静止状态猜铰链本质上是病态的**——同一堆几何可以对应多种都说得通的运动学假设，模型只能靠类别先验「蒙」。FAMOS 的解法是让输入从单状态变成「任意数量、无序、部分重叠的多状态局部点云」，并配套三个设计：不加状态序号嵌入（支持可变输入数）、状态内注意力 + 跨状态全局注意力交替（点 token 之间直接建立跨观测对应）、以及**观测运动跨度损失**——监督的不是关节限位本身，而是「这组输入里这个部件实际动过多少」，这是一个从单个观测无法作弊、必须跨状态聚合证据的目标。配合程序化数据生成器，在三个基准上全面超过重训后的多状态 Particulate 基线（ACD 上 MAO F1 64.5 vs 36.7）。

## 1. 研究背景与问题定义

### 1.1 研究问题

从稀疏单目视角建模铰接物体之所以难，在于**每次观测只揭示部分几何与部分运动证据**。现有方法两条路都有硬伤：逐物体优化的方法需要每个铰接状态的稠密多视角观测，还常假设可动部件数已知；前馈方法大多从**单次观测**推断铰接，因此严重依赖学到的类别级形状先验——换句话说，它们「猜」得多、「看」得少。视频类方法依赖人-物交互序列上的点跟踪，遮挡和多部件运动下误差会传播。

### 1.2 核心洞察：运动证据 vs 形状先验

论文的逻辑起点值得单独强调：**单状态铰接估计是本质歧义的**。一个关着的柜门，绕左铰链转、绕右铰链转、甚至向上翻，在几何上都自洽；区分它们的唯一办法是看到它动。FAMOS 的名字所代表的方法论就是「让铰接建模建立在观测到的运动上，而不是纯学出来的形状先验上」。这与 Articulate-Anything 用输入视频消解歧义的思路（见 [[Articulate-Anything - VLM驱动的URDF铰接生成]]）在动机上同源，但实现完全不同：一个是 VLM 语义推理，一个是多状态几何聚合。

### 1.3 本文核心贡献

1. **Multi-state Articulation Transformer**：处理可变数量（含单状态）的稀疏局部点云输入，状态内注意力 + 全局注意力交替；
2. **观测运动跨度（observed articulation span）目标**：设计上强制模型跨观测聚合运动线索；
3. **程序化数据生成器**：训练时在线合成无限量的自标注铰接资产，弥补真实标注数据的稀缺。

## 2. 任务定义与输入输出

输入是一小组 $S$ 个观测（不同视角、不同铰接状态），每个观测表示为共享坐标系下的局部点云 $X_s = \{x_{s,i}\}_{i=1}^N \subset \mathbb{R}^3$（可由 3D 基础模型从 casually captured 图像提升得到）。**不要求观测有序、不要求稠密、不要求部件数已知**，$S$ 可以是 1。

输出三件套：(i) 部件数 $P$（含静态基座）；(ii) 跨所有状态一致的分割 $M \in \{1,...,P\}^{S\times N}$——同一个物理部件在所有观测里被绑到同一个 query；(iii) 每部件关节参数：旋转关节用 Plücker 坐标（单位轴 $a$ + 轴上原点 $o$），平移关节用单位方向 $d$。注意 FAMOS 只覆盖 1-DoF 关节，**不预测运动限位**——它监督的「跨度」是输入相关的辅助训练目标，不是输出。

## 3. 核心方法

### 3.1 总体框架

![](assets/FAMOS%20-%20稀疏多状态观测的铰接建模/figures/02-method-pipeline.png)

> 图 2：框架总览。每个视角的局部点云经冻结 PartField 与几何嵌入编码为 point token；point token 与可学习 part queries 一起通过 Multi-state Articulation Transformer（状态内注意力与全局注意力交替 ×L 层）；per-query 头解码关节类型/轴/原点，per-point 头输出分割。
> 来源：论文 Figure 2，第 3 页，https://arxiv.org/abs/2609.20817

**点编码**。每个观测独立编码：冻结的 PartField 给出部件感知特征 $f_{s,i}$，几何嵌入 $g_{s,i} = [\gamma(x_{s,i}); \gamma(n_{s,i})]$（坐标与法向的正弦编码），拼接后线性投影成 token。**关键设计：不给 token 加观测序号/状态嵌入**。直觉是：一旦加了状态 ID，模型就可以学到「第 1 号观测负责什么、第 2 号负责什么」的捷径，推理时输入数量一变就崩。去掉状态嵌入后，「这是哪个观测」的识别只能靠状态内注意力积累的几何上下文隐式完成，天然支持任意输入数量。

### 3.2 状态内注意力与全局注意力

Transformer 的 $L=6$ 层在两种注意力间交替：

- **状态内注意力**：每个观测的 point token 独立自注意力，query 也自注意力——各自在自己的部分几何内聚合上下文；
- **全局注意力**：所有 query + 所有观测的所有 point token 拼成一个长度 $K + SN$ 的序列做联合注意力。

全局注意力的必要性论证很扎实：观测是无序且部分重叠的（可见面随视角、遮挡、状态变化），**跨观测的点级对应关系必须由点 token 之间直接建立**。这与 Particulate 等 query-based 架构形成鲜明对比——后者所有信息都经 query→point 交叉注意力路由，点 token 永远不相互注意。消融（表 4）证实：把全局注意力换成 register attention（跨观测信息必须挤过 16 个 register token 的瓶颈），ACD 上 MAO 掉 8.1 个点。

### 3.3 观测运动跨度：防作弊的监督设计

![](assets/FAMOS%20-%20稀疏多状态观测的铰接建模/figures/03-span-loss.png)

> 图 3：观测运动跨度示意。目标不是关节的固有限位，而是该部件在给定输入观测集合中覆盖的关节值范围 $\Delta_p = \max_{s \in V_p} \theta_{s,p} - \min_{s \in V_p} \theta_{s,p}$。要预测它，模型必须在每个观测里定位同一部件并推断其相对构型。
> 来源：论文 Figure 3，第 4 页，https://arxiv.org/abs/2609.20817

这是全文最漂亮的设计。作者观察到：关节类型、轴、原点都是**物体固有属性**，理论上单观测就能推出，只用它们做监督会让模型找到「只看一个观测、忽略其他」的学习捷径——实际训练中也确实如此。观测跨度 $\Delta_p$ 则不然：

- 它依赖整个输入集合（$V_p$ 是部件 $p$ 可见的观测集合，$|V_p| \ge 2$ 才有定义）；
- 观测无序，不能靠「首尾相减」近似；
- 它不等于关节限位（那是单状态方法回归的物体级属性），而是「这组输入实际展示了多少运动」。

预测它必须：跨所有观测定位同一部件 → 推断各状态下的相对构型 → 聚合。这正是我们想要的归纳偏置。还有一个细节很讲究：监督跨度而不是每观测的关节值，是因为后者要相对某个规范静止状态定义，而输入里既观察不到也不唯一确定这个状态；跨度作为关节值之差对该选择不变。

### 3.4 训练目标

匈牙利匹配同样**联合所有观测**计算（最大化全部分割对数似然），保证跨状态一致的部件-query 绑定。总损失：

$$L = \lambda_{seg}L_{seg} + \lambda_{type}L_{type} + \lambda_{rev}L_{rev} + \lambda_{pris}L_{pris} + \lambda_{span}L_{span}$$

分割与类型用交叉熵，Plücker 线与平移方向用 L1，跨度用 L1（只在 $|V_p|\ge 2$ 的部件上）。所有权重取 1.0——没有精心调权的痕迹，说明各目标本身设计对了。

### 3.5 程序化数据生成

![](assets/FAMOS%20-%20稀疏多状态观测的铰接建模/figures/04-procedural.png)

> 图 4：程序化数据生成器产出的资产示例，部件用颜色标出以展示构造即知的 GT 标注。六种解析基元（盒、柱、空柱、半环、球、带孔板）组成 15 个物体族，尺寸/部件数/关节位置逐实例随机化，训练时在线合成、确定性种子、无限不重复。
> 来源：论文 Figure 4，第 5 页，https://arxiv.org/abs/2609.20817（该图为本地文件 04-qualitative 之外的独立裁剪，见 sources.md）

用 6 种解析基元搭 15 个物体族（带铰链柜、抽屉柜、门、桌、笔记本、烤箱、洗衣机、风扇等），每实例 1–8 个可动部件，部件与关节解析放置所以标注天然精确。两阶段训练：先 50K 步纯程序化数据预训练，再 80K 步程序化 : 真实 = 1:1 混合。数据消融（表 5）显示仅加预训练就把 ACD Seg F1 从 53.2 拉到 65.3，混合训练再拉到 71.9——**程序化数据是 OOD 泛化的主要来源**。

## 4. 数据集与实验设置

**训练数据**：PartNet-Mobility（1,020 物体/25 类）+ GRScenes（968 物体/15 类）+ 程序化流。**评测**：PartNet-Mobility 测试集（76 物体/7 类，in-domain）、ACD（354 物体，几何更多样）、ArtiCraft-10K（LLM agent 程序化生成的铰接物体，6 类 × 30 = 180 物体，OOD）。

**指标**：分割 P/R/F1@IoU0.5；运动估计用递进阈值阶梯 F1——M（类型对）→ MA（+轴误差 <5°）→ MAO（+原点误差 <0.05 物体尺度），并报平均轴/原点误差与**匹配部件数 #**（防止「匹配少而简单的部件刷低误差」）。

**基线**：Particulate（在其数据上重训 + 扩展为多状态输入，最强前馈基线）；ReArt（4D 点云序列拟合，输入给 4 个完整状态）；ArtGS（3DGS 优化，输入给每状态 16 视角 + GT 部件数）。即：优化式基线拿了**更稠密更结构化的输入**仍被打败。

## 5. 实验结果

### 5.1 主要定量结果

**分割**（表 1，$S=2$）：

| 方法 | PartNet-M. F1 | ACD F1 | ArtiCraft F1 |
|---|---|---|---|
| ReArt / ArtGS | 58.2 / 55.5 | 22.5 / 24.7 | 44.1 / 47.4 |
| Particulate†（多状态版） | 93.6 | 43.7 | 76.6 |
| **FAMOS** | **98.4** | **71.9** | **92.5** |

in-domain 两者都接近天花板（98.4 vs 93.6），但跨数据集差距拉开到 28.2 与 15.9 个 F1——**多状态运动证据的价值恰恰体现在分布偏移下**，分布内先验够用时差距不大。

**运动估计**（表 2，MAO F1）：PartNet-Mobility 98.4 vs 90.3；ACD 64.5 vs 36.7；ArtiCraft 90.0 vs 68.5。且 FAMOS 匹配的部件数远多于基线（ACD 上 947 vs 572），增益不是靠挑软柿子。优化式基线在任何基准上 MAO 都低于 40。

### 5.3 消融实验

表 4（模型组件，仅用真实数据训练）与表 5（数据）联合解读：

| 变体 | PartNet-M. Seg F1 / MAO | ACD Seg F1 / MAO |
|---|---|---|
| 去掉跨度损失 | 95.1 / 93.1 | 52.3 / 41.6 |
| 换掉全局注意力 | 94.8 / 92.2 | 46.5 / 39.2 |
| 全模型 | 95.1 / 94.4 | 53.2 / 47.3 |
| + 程序化预训练 | 97.7 / 95.1 | 65.3 / 58.2 |
| + 程序化混合 | **98.4 / 98.4** | **71.9 / 64.5** |

两个组件各自贡献数个点（全局注意力在 ACD 上更关键，-8.1 MAO），而**程序化数据贡献了最大增量**（ACD MAO 47.3→64.5）。作者声称的「模型利用整组观测」与「数据弥补稀缺」两条主线都在消融中得到支持。

### 5.4 输入数量 scaling 与多状态的因果关系

![](assets/FAMOS%20-%20稀疏多状态观测的铰接建模/figures/06-multistate.png)

> 图 7：多状态推理的作用。(a) 去掉跨度损失后关节预测变差；(b) ACD 上分割与 MAO 随输入状态数增加而提升，第二个状态的增益最大，且超过训练时的 S=4 不退化；(c) 关键案例：单观测下模型给出「几何上合理但错误」的关节（椅子升降滑轨 vs 实际），加入第二状态后运动证据暴露，预测被纠正。
> 来源：论文 Figure 7，第 8 页，https://arxiv.org/abs/2609.20817

图 7(c) 是全文论点的最佳注脚：单状态歧义不是工程问题而是信息论问题，第二个状态带来的是**新信息**而不只是冗余证据。这也解释了为什么增益在第二个状态最大、之后饱和——运动自由度的歧义通常一次「动给看」就消解了。

## 6. 与相关工作的关系

- **vs Particulate**（见 [[Particulate - 前馈式三维物体铰接]]）：架构同源（query-based transformer + PartField 特征），FAMOS 的三项净增量是：多状态可变输入（去状态嵌入 + 全局注意力）、跨度损失、程序化数据。FAMOS 直接把多状态版 Particulate 作为重训基线并大幅领先，说明增量不是白给的；
- **vs Articulate-Anything / Articulate AnyMesh**：那两家用 VLM 语义推理换泛化，FAMOS 用多状态几何聚合换泛化。前者输入成本高（多轮 VLM 调用）、输出质量受限于 VLM 的 3D 推理；后者要求用户能提供两个状态的拍摄；
- **vs 优化式方法（ReArt/ArtGS）**：输入要求降了一个数量级（稀疏 casually captured vs 稠密多视角/深度），质量反而更高——前馈 + 大数据路线对逐物体优化的又一次碾压。

## 7. 局限与批判性评价

论文正文对局限的披露相对克制（结论部分较短），我的批判性评价如下：

1. **「两个状态」的获取成本被低估**（个人推断）。casually captured 听起来轻量，但要求同一物体在两个铰接状态下的可配准局部点云——真实场景中需要用户主动开合部件再拍一次，或依赖视频里的状态变化。对「静态资产批量打标」的流水线场景，这个输入要求比 Particulate 的单网格更重；
2. 只覆盖 **1-DoF 关节**，无运动限位输出。跨度是训练辅助目标而非交付物，最终资产仍需人工或后处理补限位——对比 Particulate 显式预测 $[-l_{\min},l_{\max}]$ 是功能上的退步；
3. 程序化数据的 15 个物体族都是「盒子+门/抽屉」的拓扑习语，对真正长尾的机构（剪刀、雨伞、折叠车）能否泛化存疑——ArtiCraft-10K 虽是 OOD，但它本身也是 LLM 按常见机构模板生成的，同属这个先验圈；
4. 评测全部在物体级（单物体点云），场景级多物体干扰未验证。

## 8. 复现与实践建议

- **代码**：截至 2026-10 未开源；组件（PartField、VGGT-Ω、SAM2、程序化基元库）均有开源替代；
- **算力**：4×A100 40GB，130K 步，bf16——四篇里最便宜的一篇；
- **实践建议**：如果你的输入天然是多状态的（比如机器人操作记录、视频帧序列），FAMOS 的架构假设直接匹配，收益最大；如果只有静态网格，退回 Particulate。程序化数据生成器「构造即标注 + 在线无限流」的做法对任何标注稀缺的 3D 子任务都值得抄。

## 9. 个人启发与后续问题

1. **「跨观测聚合」作为一种通用归纳偏置**：跨度损失的本质是把「必须聚合全部输入」写进损失函数。同样的 trick 可以平移到多视角一致性、多帧时序任务——任何「单样本可作弊、聚合才能做对」的场景都值得设计一个集合级辅助目标；
2. **去身份化的鲁棒性**：不给状态嵌入、不给 query 语义身份，换来对输入数量的外推（S>4 不退化）。这与 DETR 系 query 的「无身份 + 靠匹配获得意义」一脉相承，值得在我的 3D JEPA / Asset-JEPA 构想里复用（部件 token 不绑定预定义语义，靠匹配与聚合涌现）；
3. 遗留问题：跨度损失是否可以推广为「预测状态间的关节值变换矩阵」，从而在推理时直接输出限位？多状态证据与 VLM 语义先验（AnyMesh 路线）能否在同一前馈架构里融合？
