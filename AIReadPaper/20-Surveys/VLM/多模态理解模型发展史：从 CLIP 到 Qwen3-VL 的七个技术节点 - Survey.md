## 1. 文章定位：三个问题贯穿五年

原文的核心组织逻辑是**用三个问题串起五年的演进**，这也是读这篇综述最应该抓住的骨架：

1. **怎么让模型看见** —— 视觉 token 化与分辨率（区域特征 → 固定 patch → 动态分辨率 → 百万级长上下文）
2. **怎么让视觉和语言对话** —— 连接器与位置编码（跨模态注意力 → 门控 XATTN → Q-Former → 线性投影 → 原生统一；1D → 2D → M-RoPE 三维 → V2PE → Interleaved-MRoPE）
3. **怎么让理解变聪明** —— 数据、原生预训练与推理（图文对比 → 交错网页 → GPT-4 合成指令 → 原生多模态预训练 + 偏好优化 + 测试时扩展）

文章同时声明了**边界**：只谈"看懂并输出语言"，不谈"生成图像/视频"。这条边界在今天越来越难划清（统一模型 Bagel / GPT-5 两边都做），但作为理解侧的学习路径是清晰的。

## 2. 七个技术节点

### 2.1 节点一（2019–2021）：双塔对齐时代

早期形态是 **VQA**（2015 年数据集定义任务：给图 + 问题 → 答案）。2019 年的 **ViLBERT** 与 **LXMERT** 把 BERT 的成功复制到视觉：两个 Transformer 分别编码图像区域特征与文本，用 **co-attention（跨模态注意力）** 互相看对方，以 MLM + ITM（图文匹配）预训练。这是"对齐"思想的起点。

2021 年 **CLIP** 用 4 亿图文对做对比学习，图像塔（ViT/ResNet）与文本塔各自映射成向量，让配对靠近、不配对远离，训练完无需微调即可 zero-shot 分类（把类别名拼成 "a photo of a cat" 算相似度）。同年谷歌 **ALIGN** 把数据推到 18 亿弱监督图文对，证明"规模能弥补噪声"。

CLIP 的 InfoNCE 损失核心只有几行：

```python
def clip_loss(image_feats, text_feats, t=0.07):
    # image_feats / text_feats: [N, d]，已 L2 归一化
    logits = image_feats @ text_feats.T / t   # [N, N] 相似度矩阵
    labels = torch.arange(N)                  # 对角线是正样本对
    loss_i = F.cross_entropy(logits, labels)  # 图像侧
    loss_t = F.cross_entropy(logits.T, labels)# 文本侧
    return (loss_i + loss_t) / 2
```

![](assets/多模态理解模型发展史：从%20CLIP%20到%20Qwen3-VL%20的七个技术节点%20-%20Survey/figures/02-clip-contrastive-pretraining.png)

> CLIP 的核心思想一图看懂。左：对比预训练——$N$ 个图像与 $N$ 段文本分别过编码器，算出 $N \times N$ 相似度矩阵，对角线（配对样本）取最大，即 InfoNCE；右：零样本推理——把类别名套进 "A photo of a {object}" 模板过文本编码器，图像向量与各类别向量比相似度即可分类，完全不需要训练分类头。来源：CLIP Figure 1（arXiv:2103.00020, p.2）。

**致命短板**：只会算相似度，不会生成句子。CLIP 能回答"这张图和哪句话最像"，却答不了"图里几个人在干什么"。

> 记忆点：双塔对齐是**嵌入层**的革命——把视觉与语言放进同一向量空间，但输出被锁死在"匹配"上，生成能力为零。

### 2.2 节点二（2022）：Flamingo，多模态的 GPT-3 时刻

DeepMind 的 Flamingo 第一次把"看图 + 自由文本生成"合体，32 个示例即可超过当年精调的专用模型。核心思想是：**一个已经会说话的 LLM（Chinchilla 70B）不需要重新学说话，只要给它"插上眼睛"**。

三个关键设计：

![](assets/多模态理解模型发展史：从%20CLIP%20到%20Qwen3-VL%20的七个技术节点%20-%20Survey/figures/03-flamingo-architecture.png)

> Flamingo 架构总览。左下：视觉编码器（❄ 冻结）→ Perceiver Resampler（紫色，从头训练）；右侧：LM block（❄ 冻结）与 GATED XATTN-DENSE（紫色，从头训练）交替堆叠；底部是图文交错输入 `<image> This is a very cute dog. <image> This is`，顶部输出自由文本。注意它与单流模型的关键差别——文本 token 不与视觉 token 拼在同一条序列里，视觉信息只通过层间交叉注意力注入。来源：Flamingo Figure 3（arXiv:2204.14198, p.4）。

- **双冻结**：视觉编码器（NFNet-F6，CLIP 式对比预训练）与 LLM 全部冻结，只有新增模块（约 10B 参数）参与训练。
- **Perceiver Resampler**：用 64 个可学习 query 做交叉注意力，把任意数量的变长时空视觉特征压缩成**固定 64 个视觉 token**。
- **Gated Cross-Attention**：插在冻结 LLM 层之间，输出经 $\tanh(\alpha)$ 门控，$\alpha$ 初始化为 0 —— 训练初期新模块对 LLM **零影响**，随训练逐渐"开闸放水"，保证不破坏预训练语言能力。

```python
def gated_xattn_dense(h_text, v_tokens, alpha):
    q = Wq(h_text); k = Wk(v_tokens); v = Wv(v_tokens)
    x = scaled_dot_product_attention(q, k, v)   # 交叉注意力
    x = x + h_text                              # 残差
    x = FFN(x) + x                              # Dense 块
    return h_text + tanh(alpha) * x             # 门控：α 初始为 0
```

![](assets/多模态理解模型发展史：从%20CLIP%20到%20Qwen3-VL%20的七个技术节点%20-%20Survey/figures/04-flamingo-gated-xattn-dense.png)

> GATED XATTN-DENSE 层的内部结构与右侧伪代码一一对应：交叉注意力从视觉特征取 K/V、语言输入取 Q，随后 tanh gating（α 初始化为 0）逐门放行；❄ 表示冻结的 self-attention / FFW。这就是"训练初期新模块对 LLM 零影响、随训练逐渐开闸"的实现细节。来源：Flamingo Figure 4（arXiv:2204.14198, p.5）。

数据侧贡献同样关键：从 4300 万网页挖出图文交错的 **M3W（MultiModal MassiveWeb）**，配合**分块注意力掩码**（文本 token 只 attend 前面最近那张图）支持任意交错序列。

> 代价：Perceiver 的强压缩丢细粒度空间信息、推理开销大 —— 这正是下一代要解决的。

### 2.3 节点三（2023 上）：BLIP-2 与 LLaVA，开源复现与数据为王

**BLIP-2（Q-Former）**：188M 小 Transformer，32 个可学习 query。图像特征作 K/V，query 通过交叉注意力"抽取"与语言最相关的视觉信息。三目标联合训练，用不同注意力掩码隔开防泄漏：

```python
# 阶段一：图像编码器冻结，Q-Former 三目标联合
loss_itc = contrastive_loss(q_output, text_output)      # 图文对比
loss_itm = binary_cross_entropy(match_logit, is_match) # 图文匹配（二分类）
loss_itg = lm_loss(text_tokens, cond=q_output)         # 图文生成
loss = loss_itc + loss_itm + loss_itg
# 阶段二：接冻结 LLM，query 输出当"软提示"训练生成
```

Q-Former 本质是**信息瓶颈**：过滤与语言无关的底层视觉噪声，只保留 LLM 用得上的语义。

![](assets/多模态理解模型发展史：从%20CLIP%20到%20Qwen3-VL%20的七个技术节点%20-%20Survey/figures/05-blip2-qformer-and-objectives.png)

> 左：Q-Former 架构——Learned Queries 与文本共享一套 self-attention / cross-attention / FFN，图像特征只进 cross-attention 的 K/V；右侧三种注意力掩码分别对应 ITC（双向）、ITG（多模态因果）、ITM（单向）。这正是原文说的"三个目标用不同的注意力掩码隔开，防止互相泄漏"的实现。来源：BLIP-2 Figure 2（arXiv:2301.12597, p.3）。

**LLaVA**：把架构简化到极致 —— CLIP ViT-L/14 + **一层线性投影** + Vicuna，视觉 token 直接拼在文本前面进 LLM。真正贡献在**数据**：用 GPT-4 把 COCO caption 改写成多轮对话（LLaVA-Instruct-158K）。两阶段训练：

![](assets/多模态理解模型发展史：从%20CLIP%20到%20Qwen3-VL%20的七个技术节点%20-%20Survey/figures/06-llava-network-architecture.png)

> LLaVA 的全部架构就这么多：图像 $X_v$ 过 CLIP ViT-L/14 得视觉特征 $Z_v$，经一个可训练投影矩阵 $\mathbf{W}$ 映射进词嵌入空间得到 $H_v$，与语言指令 $X_q$ 的 token 拼接后一起送进 LLM $f_\phi$（Vicuna）。没有 Resampler、没有 Q-Former、没有交叉注意力层。来源：LLaVA Figure 1（arXiv:2304.08485, p.4）。

```python
# 阶段一：特征对齐，冻结 ViT 与 LLM，只训投影层（558K 图文对）
h = projector(vit_frozen(img)); loss = lm_loss(llm_frozen(h + embed(cap)))
# 阶段二：端到端微调，冻结 ViT，训投影 + LLM（158K 指令数据）
h = projector(vit_frozen(img)); loss = lm_loss(llm_trainable(h + embed(conv)))
```

> 原文给的最重要结论：**在大模型时代，指令数据的质量与多样性比连接器的复杂度更重要**。LLaVA 用最朴素架构追平花哨桥接方案。LLaVA-1.5（2023.10）换成两层 MLP、分辨率提到 336、加入学术数据集，成为开源社区事实标准。

### 2.4 节点四（2023 下）：GPT-4V 与 Gemini，原生多模态宣言

**GPT-4V**（2023.09）技术细节未公开，从行为看是把视觉编码器输出接入 GPT-4 的 token 流，支持多图、画框、空间关系推理。意义在于证明：**视觉理解可以共享 LLM 的推理能力**，而非一个单独的识别模块。

**Gemini 1.0**（2023.12）提出 **natively multimodal**：不是"先有 LLM 再嫁接眼睛"，而是从一开始就训练统一处理文本 / 图像 / 音频 / 视频的模型，所有模态 token 化后进入同一个 Transformer。音频直接用 16kHz 波形，视频就是帧序列。

**两条路线对比**

| 维度 | 拼接式（Flamingo / LLaVA） | 原生式（Gemini / GPT-5） |
|---|---|---|
| 训练起点 | 复用预训练 LLM + 预训练视觉编码器 | 统一模型从头训练，模态同时学习 |
| 模态对齐 | 靠连接器事后对齐，有信息损失 | 预训练中自然涌现跨模态关联 |
| 成本 | 低（只训连接器） | 极高（全模态一起训） |
| 上限 | 受限于骨干 LLM 能力 | 能力随数据规模整体提升 |

原生多模态的好处是**零信息损失**：不经过"视觉特征 → 语言语义"的压缩瓶颈，直接在统一表示上推理。这也解释了为什么 Gemini 2.5 / GPT-5 之后，"文本能力"和"视觉能力"不再分家。

### 2.5 节点五（2024）：Qwen2-VL 与 InternVL，任意分辨率与三维位置编码

2024 年还剩两个硬伤：**固定分辨率**（224×224 缩放让文档、小字、密集图表糊成一片）和**位置编码一维化**（丢失图像的二维空间结构）。

**Naive Dynamic Resolution**：去掉 ViT 的绝对位置编码、改用 **2D-RoPE**，ViT 可接受任意尺寸图像，按实际分辨率切 patch 产生**可变数量**视觉 token，再用 MLP 把相邻 2×2 patch 合并成 1 个 token。

```python
def visual_tokens(h, w, patch=14):
    ph, pw = ceil(h / patch), ceil(w / patch)  # 按真实分辨率切，不统一缩放
    th, tw = ceil(ph / 2), ceil(pw / 2)        # 2x2 合并
    return th * tw + 2                         # +2 是起止特殊 token
    # 224x224 → 66；448x896 → 512；1000x1000 → 约 2560；单图上限 16384
```

![](assets/多模态理解模型发展史：从%20CLIP%20到%20Qwen3-VL%20的七个技术节点%20-%20Survey/figures/08-qwen2vl-dynamic-resolution.png)

> 动态分辨率的直接收益：无论小图、长宽比极端的截图还是高分辨率文档，Qwen2-VL 都能按原生比例理解内容，不再被统一缩放到 224×224 而糊掉小字。来源：Qwen2-VL Figure 2（arXiv:2409.12191, p.4）。

**M-RoPE**：把旋转嵌入拆成**时间 t、高度 h、宽度 w** 三个分量：

- **文本**：三分量用相同位置 ID → 退化为 1D RoPE，与纯文本 LLM 兼容；
- **图像**：时间 ID 恒定，高度/宽度 ID 按二维坐标递增；
- **视频**：时间 ID 随帧号递增 → 位置编码天然三维。

好处是同一套位置系统统一三种模态，且图像/视频位置 ID 数值小、便于长序列外推。视频侧配合 2 FPS 采样 + 3D 卷积，Qwen2-VL 能理解 20 分钟以上长视频，并让 **grounding**（直接输出 $(x_1,y_1,x_2,y_2)$ 坐标框）成为可能。

**InternVL 1.5/2 的另一条路**：动态 tiling（大图切若干 448×448 瓦片 + 全局缩略图）+ **pixel unshuffle**（每 tile 从 1024 token 降到 256，即 1/4）。在 OCR / 文档理解上同样拔群，与"固定 patch"生态兼容性好。

### 2.6 节点六（2025 上）：Qwen2.5-VL 与 InternVL3，效率、时间感知与原生预训练

**Qwen2.5-VL（2025.01）** 做三件事：

- **窗口注意力**：原生动态分辨率 ViT 中只有 4 层全注意力，其余用窗口注意力（最大 8×8 patch = 112×112 像素），把 ViT 复杂度从**平方级降到线性级**；
- **绝对时间对齐**：M-RoPE 时间分量直接对齐真实时间戳，视频按内容动态调整采样 FPS（快动作多采、静止少采），可对几小时视频做秒级定位；
- **更强感知**：3D grounding、文档/表格/图表解析、GUI 操作，能力从"看"走向"用"。

**InternVL3（2025.04）** 把"原生多模态"带进开源：

- **原生多模态预训练**：不再先训纯文本 LLM 再嫁接，而是把约 50B 纯文本 token 与约 150B 图文/视频/交错数据**在同一预训练阶段混合训练**（约 3:1）。仅靠这一点，InternVL3 的纯文本能力就超过了其语言底座 Qwen2.5 本身；
- **V2PE（可变视觉位置编码）**：视觉 token 位置增量不再是 1，而是更小的分数 $\delta \in \{1/2, 1/4, \dots, 1/256\}$，同一上下文窗口可塞进更多视觉 token；
- **MPO（混合偏好优化）**：针对"训练看真实 token、推理看自己生成 token"的分布偏移，用正负样本对做偏好优化；
- **测试时扩展**：用 VisualPRM-8B 做裁判，Best-of-N 选最优答案。

```python
# V2PE：视觉 token 用分数增量，文本 token 增量恒为 1
pos = 0
for tok in sequence:
    if tok.is_text: pos += 1.0          # 文本：标准步长
    else:           pos += delta        # 视觉：delta ∈ {1/2, 1/4, ..., 1/256}
    tok.pos_id = pos
```

### 2.7 节点七（2025 下–2026）：Qwen3-VL / GPT-5 / Gemini 3，推理与智能体

**Qwen3-VL-235B-A22B**（MoE，激活 22B，2025.09）三大架构升级：

- **Interleaved-MRoPE**：在 M-RoPE 基础上把时间/高/宽三分量的频率**全频段分配**，长视频推理与跨模态对齐更强；
- **DeepStack**：不再只用 ViT 最后一层特征，而是**多层 ViT 特征融合**后送入 LLM，细粒度细节（小字、细纹、遮挡边缘）大幅提升；
- **Text–Timestamp Alignment**：视频理解从"相对帧号"进化为"文本时间戳对齐"，可直接回答"第 15 分钟穿红衣服的人做了什么"；
- **Instruct / Thinking 双版本**：Thinking 版针对 STEM 与数学深度推理优化，MathVista / MMMU 达 SOTA；
- **原生 256K 上下文（可扩 1M）**：一次吃下数百页文档或 2 小时视频；OCR 支持 32 种语言；支持 2D/3D grounding 与 OS World 级 GUI 智能体操作。

**GPT-5（2025.08）**：文本/图像/音频统一 tokenizer，单一模型原生处理所有模态，推理模式与普通模式共享同一套权重 —— 多模态不再是"LLM + 附件"，而是模型的本体。**Gemini 3（2025.11）** 同样原生多模态 + 强化推理。这条线印证了 Gemini 1.0 的判断：**原生统一是终局**。

## 3. 四条主线 × 七个节点总表

| 节点 / 年份 | 代表模型 | 架构突破 | 视觉 Token 化 | 位置编码 | 训练范式 |
|---|---|---|---|---|---|
| 2019–2021 | ViLBERT / CLIP / ALIGN | 双塔 + 跨模态注意力 | 区域特征 / 固定 patch | 绝对位置 | 对比学习（无生成） |
| 2022 | Flamingo | 冻结骨干 + 门控交叉注意力 | Perceiver 压缩为 64 token | 1D | 图文交错 few-shot |
| 2023 上 | BLIP-2 / LLaVA | Q-Former / 线性投影 | 32 query / 全量 token | 1D | 两阶段：对齐 + 指令微调 |
| 2023 下 | GPT-4V / Gemini 1.0 | 统一 Transformer（原生） | 统一 token 空间 | 统一位置 | 从零全模态预训练 |

## 4. 十问十答：原文最有价值的部分

原文第十节按「基础原理 → 注意力与架构 → 训练目标与损失 → 推理与工程 → 高阶对比」五组展开十个原理问题。以下是压缩后的要点。

### 4.1 Q1 跨模态对齐与 InfoNCE

**跨模态对齐**：让不同模态的表示在共享语义空间里形成对应关系。CLIP 用 InfoNCE 实现：batch 内 $N$ 个图文对，点积得 $N \times N$ 相似度矩阵，让对角线最高 —— 等价于一个 $N$ 分类问题。

对比学习适合做对齐的四个原因：

1. **目标匹配任务本质**：对齐要的是"对应关系"而非"重建"，绕开像素/波形重建的高成本与无关细节；
2. **能吃海量弱监督数据**：负样本足够多时，个别错误正对影响很小；
3. **嵌入紧凑可迁移**：产出稠密向量，支持零样本分类、图文检索，也能作下游多模态模型初始化；
4. **框架统一**：与单模态自监督对比（SimCLR 等）同一套数学框架。

### 4.2 Q2 双塔 vs 单流

| 维度 | 双塔（CLIP） | 单流（LLaVA / Qwen-VL） |
|---|---|---|
| 融合时机 | 最终嵌入点积（一次） | 每一层自注意力（逐层） |
| 交互深度 | 浅（晚融合） | 深（早融合） |
| 生成能力 | 无 | 有（自回归） |
| 检索 / 嵌入 | 天然支持 | 需额外设计 |
| 计算成本 | 低（两塔并行） | 高（序列变长） |
| 典型任务 | 分类 / 检索 / 对齐 | 对话 / 推理 / 细粒度理解 |

Flamingo 是**中间态**：文本自注意力保持 LLM 结构，视觉通过插入层间的门控交叉注意力注入 —— "浅注入、深生成"。

### 4.3 Q3 LLaVA 里图像 token 的掩码规则

两个结论：**图像 token 之间不施加因果掩码（双向可见）；图像 token 看不到后面的文本 token**。

- 图像是一次性给定的完整条件，不是逐块生成的序列 → 全可见才能整合整幅图上下文；
- 文本是自回归生成的，且排在视觉 token 之后 → 视觉天然看不到文本；
- 文本 token 可 attend 前面全部图像 token → 实现"看图说话"。

```
# 序列：[img1 ... imgK, tok1 ... tokL]
#        img1 imgK tok1 tok2
# img1    ✓    ✓    ✗    ✗     ← 视觉行：只看视觉，看不到文本
# tok1    ✓    ✓    ✓    ✗     ← 文本行：看全部视觉 + 之前文本
# 视觉块内全 ✓（无因果）；文本块内严格下三角（因果）
```

即"**前缀条件 + 自回归解码**"的标准结构：视觉是前缀，文本是解码目标。

### 4.4 Q4 交叉注意力 vs 自注意力，Perceiver 为什么压缩

**模态内自注意力**：Q/K/V 全来自同一序列。**交叉注意力**：Q 来自一个模态（文本），K/V 来自另一模态（视觉）。

Perceiver Resampler 用固定 64 个可学习 query 把变长视觉特征重采样为固定 token。压缩的三条必要性：

1. **计算量**：LLM 每层都要与视觉交互，几千视觉 token 会让注意力开销随长度平方增长；
2. **信息筛选**：视觉特征里大量冗余低层纹理，压缩器相当于可学习"信息瓶颈"；
3. **长度可控**：固定输出让 batch 内长度整齐。

代价是丢细粒度空间信息 —— 这也是 Qwen2-VL 改走"不压缩、动态打包"路线的原因之一。

### 4.5 Q5 预训练对齐阶段 vs 指令微调阶段

| 维度 | 预训练对齐 | SFT 指令微调 |
|---|---|---|
| 训练目标 | 建立模态对应，学视觉—语言联合表征 | 学会跟随指令、对话格式、任务泛化 |
| 数据类型 | 海量图文对 / 弱监督交错数据（百万~数十亿） | 高质量人工 + 合成指令数据（十万~百万级） |
| 损失函数 | 对比损失 / ITM / MLM / 条件生成 | 统一自回归 LM loss |
| 训练对象 | 连接器为主（部分训视觉编码器） | 连接器 + LLM（视觉编码器常冻结） |
| 效果 | 能"看图说话"但不会聊天 | 具备对话 / 推理 / 工具能力 |

一句话：**预训练教模型"看见并对应"，SFT 教模型"听懂人话并回答"**。两者通常只对文本 token 计算损失，视觉 token 只作条件。

### 4.6 Q6 模态坍塌

**模态坍塌（modality collapse）**：训练中退化到只依赖某一种模态。最典型是**视觉被忽略** —— 把图像换成噪声甚至不输入，模型照样"答对"大部分 VQA，因为答案完全来自语言先验。

诱因：数据失衡（纯文本远多于图文）、语言先验过强（VQA 存在"仅凭问题就能猜"的捷径）、连接器过弱（压缩过狠）、长期冻结视觉编码器。

缓解：数据平衡与采样（如 InternVL3 的 3:1）、**模态 dropout**（随机丢图，强制"有条件时才用视觉"）、增加必须看图才能答对的样本（grounding / 计数 / 细粒度 OCR）、后期解冻联合训练、去偏数据。

### 4.7 Q7 Prefill 阶段的注意力规则

多模态 Decoder-Only 推理分 **Prefill**（一次性并行处理全部输入，产出 KV cache）与 **Decode**（逐 token 自回归）。Prefill 规则与训练一致：

- 整条序列用因果掩码，但**视觉块内部例外**（图像 token 互相全可见）；
- 图像 token 不 attend 文本（被因果掩码挡住）；
- 每个文本 token attend 前面所有图像 + 文本 token。

工程含义：图像 token 的 KV 在 Prefill 一次性算完并缓存，Decode 每生成一 token 只需增量计算 —— 所以**视觉 token 数量直接决定 Prefill 显存与首 token 延迟**。

### 4.8 Q8 OCR 弱与细节幻觉的算法原因

**幻觉**指生成图片中不存在的内容。三个层面：

- **特征对齐**：视觉编码器输出与 LLM 词嵌入空间存在"语义鸿沟"，强压缩连接器丢小字/小物体/边缘细节，位置编码错位进一步破坏空间对应；
- **训练数据**：caption 噪声（描述图中没有的物体）、共现偏置（"操场"常配"足球"）、SFT 中幻觉式回答被当作正确答案训练（等于显式强化幻觉）、密集小字样本不足；
- **注意力机制**：视觉 token 上千时 softmax 被稀释，文本实际"看到"的视觉信息很少；长序列易出现 attention sink，视觉条件被语言先验接管。

缓解：grounding / 指认监督、反幻觉负样本（图文不匹配对）、注意力重加权、解码时不确定性检测与校准。

### 4.9 Q9 三种连接器方案对比

| 维度 | CLIP 对比对齐 | BLIP-2 Q-Former | LLaVA 直接投影 |
|---|---|---|---|
| 原理 | 双塔对比，全局向量对齐 | 32 query 交叉注意力抽取 | 线性 / MLP 逐 token 映射 |
| 视觉信息保留 | 全局级（丢空间细节） | 强压缩（细粒度丢失） | 全量保留（可细粒度） |
| 训练复杂度 | 低 | 高（三目标两阶段） | 中（两阶段） |
| 推理开销 | 低（单向量） | 低（32 token） | 高（token 多） |
| 优点 | 可检索、零样本分类 | 高效、可接任意 LLM、滤噪 | 简单、细节好、可端到端 |
| 缺点 | 无生成、粒度粗 | 细粒度弱、训练繁琐 | token 多、需大量对齐数据 |
| 适用 | 检索 / 分类 / 特征提取 | 高效通用理解、超大 LLM 对接 | OCR / 文档 / 定位 / 开源主流 |

### 4.10 Q10 上下文窗口瓶颈与降 token 三方案

**瓶颈**：自注意力计算与显存随序列长度平方增长。一张 4096×4096 图（patch=14）约产生 **8.6 万个** patch token —— 比一本书还长，直接爆显存。

三种算法层降 token 方案：

1. **相邻 patch 合并 / pixel unshuffle**：2×2 合并为 1，token 数降为 1/4，不损失局部结构（Qwen2-VL 的 MLP 压缩、InternVL 的 pixel unshuffle）；
2. **可学习查询重采样**：固定 $M$ 个 query 交叉注意力把 $N$ 个视觉 token 重采样为 $M$ 个（Perceiver 64、Q-Former 32），同时实现压缩 + 信息筛选；
3. **动态分辨率 + token 预算控制**：按内容分配算力 —— 大图切 tile + 全局缩略图（InternVL），或 `min_pixels` / `max_pixels` 限制每图 token 上限（Qwen2-VL 默认 4~16384）。

扩展方向：窗口注意力（Qwen2.5-VL 把 ViT 降到线性）、token 剪枝、V2PE 分数位置增量。

## 5. 延伸：从"理解"走向"空间与行动"

原文停在了 Qwen3-VL / GPT-5 这一层，但这条技术线接下来要回答的问题，和旭涛关注的方向高度重合。以下是四条我认为最值得继续追的延伸线索。

### 5.1 延伸一：理解 → 空间智能，是 3D 研究者的接口

原文的七个节点**全部停留在 2D 图像 / 视频**。但 M-RoPE 的"时间 × 高 × 宽"三维位置编码、Qwen2.5-VL 的 3D grounding、Qwen3-VL 的 2D/3D grounding，本质上都在做同一件事：**把像素坐标提升成可推理的几何量**。

这条线再往前一步就是**空间智能（spatial intelligence）**：

- 单目深度与前馈重建（参见 [[从 Depth Anything 到 DA3：前馈深度与三维几何 - Survey]]、[[前馈式三维重建 - 分支谱系总览]]）已经能提供 metric depth 与相机位姿；
- VLM 的 grounding / pointing 能力正在从 2D box 走向 3D box、走向像素级 correspondence 与相机位姿（参见 [[VLM³ - 原生三维学习的视觉语言模型]]）；
- 反过来，3D 表征（点云 / 3DGS / mesh）进入 LLM token 空间的代价问题，见 [[三维多模态大语言模型架构 - Survey]] —— 一个 5000 面网格在 OBJ 文本方案下要 3.7 万 token，这个量级恰好落在 Q10 讨论的"上下文窗口瓶颈"里。

**判断**：原文讨论的"降 token 三方案"（合并 / 重采样 / 动态预算）对 3D-LLM 是**直接复用**的。3D 侧真正独特的是"几何保真"这一重约束 —— 视觉 token 压缩丢的是细节，3D token 压缩丢的是拓扑。

### 5.2 延伸二：理解 → 行动，VLA 是下一个分水岭

Qwen3-VL 的"OS World 级 GUI 智能体操作"已经是**行动**了，只是动作空间在屏幕。把动作空间换成机械臂，就是 VLA（[[RT-2 - Web知识迁移视觉语言动作模型]]、[[StarVLA 系列 - Survey]]、[[ByteDance GR 系列 - Survey]]）。

关键延续点：

- **VLM 的视觉 token 预算直接决定 VLA 的控制频率**。RT-2 把动作离散成文本 token 与视觉语言数据共同微调；而 VLA 要跑 10Hz 以上，token 数与延迟是硬约束 —— Q10 的三个降 token 方案在机器人上从"省钱"变成了"能不能实时"。
- **模态坍塌在 VLA 上更危险**：机器人任务里"不看图也能蒙对"的捷径更多（因为 proprioception 与语言先验都很强），Q6 的模态 dropout 在具身场景几乎是必需品。
- **视频时间戳对齐（Qwen3-VL 的 Text–Timestamp Alignment）对长程操作任务有直接价值**：机器人需要"第 37 秒时夹爪碰到杯子了吗"这种秒级定位。

### 5.3 延伸三：理解 vs 生成的边界正在消失

原文明确划了边界（只讲理解），但 2025–2026 的现实是：**统一模型两边都做**。

- [[Bagel - 统一多模态理解与生成预训练]] 用 MoT 架构 + 双编码器（SigLIP2 语义 + FLUX VAE 像素）+ Next-Group-of-Token 预测，涌现出自由图像编辑、未来帧预测、3D 操控；
- GPT-5 / Gemini 3 的"统一 tokenizer"也是同一趋势。

对理解侧的直接影响是：**"理解"不再只是输出文本，也可以是输出 latent / 输出动作 / 输出结构化坐标**。原文的 Q3（视觉是前缀、文本是解码目标）这个二分结构，在统一模型里会被打破 —— 前缀与解码目标可以是任意模态的混合。

而世界模型（[[生成式世界模型路线的前馈三维重建 - Survey]]）则把"理解"进一步推向"预测未来"：理解一个场景的最高标准，是能预测干预之后它会变成什么样。

### 5.4 延伸四：给面试与复现的三条实操建议

原文的结语给了一条复现路径，我按旭涛的使用场景补两条：

1. **复现顺序**：先跑通 CLIP 对比损失（30 行，能建立"对齐 = 对比 = N 分类"的直觉）→ 写一个 LLaVA 风格两阶段训练（关键是理解"只对答案部分算 loss"与视觉前缀的掩码）→ 读 Qwen2-VL 的 M-RoPE 源码（三维位置 ID 分配是理解多模态位置编码最具体的一课）。这条路径恰好就是这段历史本身。
2. **面试高频**：Q2（双塔 vs 单流的融合时机）、Q3（图像 token 的掩码规则）、Q6（模态坍塌的诱因与缓解）、Q9（三种连接器取舍）是 VLM 岗位最常被追问的四个；Q10（降 token 三方案）则是工程岗的加分项。
3. **一句话总纲**：五年演进回答三个问题 —— **怎么看见**（视觉 token 化）、**怎么对话**（连接器 + 位置编码）、**怎么变聪明**（数据 + 原生预训练 + 推理）。

## 6. 局限与评价

原文是一篇质量不错的**入门到进阶纵向综述**，优点与短板都很明确。

**优点**

- 时间线清晰，七个节点每个都给了"解决什么问题 + 关键架构细节 + 训练方法"三层，配伪代码，可复现性强；
- 第十节"十问十答"是全文最有价值的部分，覆盖了原理、掩码、损失、推理工程四个层面，且都能对应回具体模型；
- 四条主线（架构 / token 化 / 位置编码 / 训练范式）的抽象方式很好，能让人把新论文快速归位。

**局限**

1. **科普定位，深度有限**：对每个模型只给骨架，没有实验数字、没有消融，也没有讨论失败案例。想深挖应转 [[VLM技术谱系与2026前沿格局 - Survey]]。
2. **部分表述需要校准**：
   - 原文称 Qwen2-VL "224×224 → 66 tokens"与"单图最多 16384"，是官方口径，但 16384 是 token 上限而非常见配置，实际使用中 `min_pixels`/`max_pixels` 才是控制手段；
   - 原文把 InternVL3 的"原生多模态预训练"描述为 50B 文本 + 150B 多模态（3:1），这个配比是原文给出的口径，需以官方技术报告为准；
   - "Gemini 3（2025.11）"、Qwen3-VL "235B-A22B" 等属于 2025–2026 快速迭代期的信息，引用前建议核对官方发布页。
3. **只讲理解，不讲生成**：这在 2026 年已经是偏保守的切分（见 5.3）。
4. **缺失视角**：没有讨论**评测**（基准饱和、语言先验泄漏）、**数据治理**（CapFilt 一类的数据自举，见 [[BLIP 系列：从数据自举到统一理解生成 - Survey]]）、**长上下文的真实工程成本**，也没有讨论开源与闭源的能力差距来源。

**总体判断**：★★★★☆。作为"把 VLM 五年历史一次性捋顺"的入口文章是优秀的，尤其是十问十答部分建议精读；但它是一张**地图**，不是**地形**。真正要用起来，需要配合横向谱系综述与具体论文笔记。
