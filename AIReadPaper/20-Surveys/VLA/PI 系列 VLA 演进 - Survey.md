## 一句话结论

PI 系列不是一条单纯“把 VLM 做大、把机器人数据做多”的路线，而是依次重写了三个接口：π0 重写**动作接口**，用 flow matching 生成连续动作；π0.5 重写**数据接口**，让 Web、跨本体、多环境与高层语义监督共同迁移到机器人；π*0.6 重写**学习接口**，让策略从自主执行、奖励和人工纠正中改进；π0.7 则用语言、视觉子目标和质量元数据给异质数据消歧，把这些能力汇成一个可操控的通用策略。

## 1. 总体演进：六次瓶颈转移

### 1.1 不是模型列表，而是问题不断转移

PI 系列真正的主线可以概括为六次瓶颈转移：

1. **π0：动作怎么生成？** 用 flow matching action expert 取代逐维离散动作 token，解决高频、连续和灵巧控制。
2. **FAST / Knowledge Insulation：动作知识怎么高效写入 VLM，又不破坏 VLM？** FAST 改进动作 token，KI 隔离连续动作梯度。
3. **Hi Robot / π0.5：机器人怎么走出实验室？** 引入高层语言子任务、Web 数据、多环境与跨本体数据，解决开放世界与长程任务。
4. **RTC / π*0.6：会做之后，怎样跑得实时、稳定、可靠？** RTC 吸收推理延迟；Recap 让策略从失败、纠正和自主实践中改进。
5. **MEM / Human-to-Robot：数据和上下文如何继续扩展？** 用视频与文本记忆覆盖分钟级历史，并把人类视频变成新的技能来源。
6. **π0.7：怎样混合所有数据而不把策略平均成平庸行为？** 用详细语言、质量/速度/错误元数据、控制模式与视觉子目标显式区分不同行为模式。

### 1.2 时间线

| 时间 | 工作 | 核心变化 | 解决的瓶颈 | 新暴露的问题 |
|---|---|---|---|---|
| 2024-10 | π0 | PaliGemma 3B + 约 300M flow action expert | 离散动作难以支持高频灵巧控制 | 连续动作训练慢，可能干扰 VLM 表征 |

| 2025-02 | Hi Robot | 高层 VLM 理解复杂指令与反馈，低层 π0 执行 | 平坦 VLA 难做开放式、多阶段任务 | 高低层分离，语言接口有损 |
| 2025-04 | π0.5 | 异构 co-training、显式子任务、FAST + flow | 未见住宅、未见物体和长程家务 | 两阶段训练复杂，主干仍可能遗忘 |

| 2026-10 | Pi API beta | 托管微调和云端推理 | 从研究模型走向平台化部署 | 不是新的模型世代 |

## 2. π0：建立连续动作 VLA 的基本骨架

### 2.1 模型结构

π0 是约 **3.3B 参数**的 VLA：PaliGemma 3B 负责图像与语言语义，约 300M 参数的 action expert 负责连续动作生成。输入包括 2–3 路 RGB 图像、语言指令和本体状态；输出是长度 $H=50$ 的动作块。

模型用 conditional flow matching 学习从高斯噪声到真实动作块的速度场。对真实动作 $A$、噪声 $\epsilon$ 和 flow 时间 $\tau$：

$$A^\tau=\tau A+(1-\tau)\epsilon$$

训练目标让 action expert 预测速度：

$$v_\theta(A^\tau,o,\tau)\approx A-\epsilon$$

推理从高斯噪声开始，<span class="md-comment-hl" data-comment="10次Euler积分是如何工作的？" title="💬 10次Euler积分是如何工作的？">用约 10 次 Euler 积分得到连续动作</span>。相比逐 token 解码，动作专家可以在较少步骤内一次生成整段高频轨迹。

> 💬 **批注**（针对「用约 10 次 Euler 积分得到连续动作」）：10次Euler积分是如何工作的？

![](assets/PI%20系列%20VLA%20演进%20-%20Survey/figures/01-pi0-overview.png)

> **图 1：π0 总览。** PaliGemma VLM 继承 Web 视觉语言知识，独立 action expert 通过 flow matching 生成连续动作；跨本体数据使一个模型能够服务单臂、双臂和移动操作平台。  
> 来源：π0 论文 Figure 1，<https://arxiv.org/abs/2410.24164>

### 2.2 数据与能力

π0 使用约 10,000 小时机器人数据，其中自有数据约 903M 时间步，覆盖 7 类机器人配置与 68 个任务，并混合 OXE、Bridge V2、DROID 等开放数据。所有状态和动作填充到统一的最大维度，低维本体使用 mask 或零填充。

这一代验证了三件事：

- 大 VLM 可以作为机器人策略的语义主干；
- 连续 action chunk 比逐步离散动作更适合高频灵巧控制；
- “大规模跨本体预训练 + 高质量下游后训练”在机器人领域成立。

### 2.3 留下的问题

π0 的 action expert 从随机初始化开始。连续 flow loss 若直接传回主干，会产生不利的学习动力学：训练慢、语言跟随下降、Web 预训练知识被侵蚀。后续 FAST 和 Knowledge Insulation 都是在解决这个结构性矛盾。

## 3. FAST / π0-FAST：训练快，但不是推理快

### 3.1 为什么朴素动作 token 会失败

高频机器人轨迹通常非常平滑。若把每个时间步、每个动作维度独立分箱，模型会看到大量几乎重复的 token。控制频率越高，复制上一个 token 越容易降低损失，却越难学到整段轨迹的结构。

50 Hz、14 维双臂动作的一秒序列，朴素表示需要 $50\times14=700$ 个 token。FAST 的目标不是增加分箱精度，而是先压缩时间序列，再让 Transformer 预测有信息量的频率成分。

### 3.2 FAST 的动作编码

FAST 的流程为：

1. 每个动作维度按 1%/99% 分位数归一化；
2. 沿时间轴执行 DCT，把轨迹能量集中到低频；
3. 对 DCT 系数缩放并取整，使微小高频系数变成零；
4. 按“频率优先”展开，先预测整体轨迹形状，再预测细节；
5. 用 BPE 合并重复零值和常见系数组合。

上述 700 个 token 可压缩到平均约 53 个。FAST+ 又在约 100 万条真实机器人动作轨迹上训练通用 BPE 词表，使 tokenizer 能跨机器人、动作空间和控制频率复用。

![](assets/PI%20系列%20VLA%20演进%20-%20Survey/figures/02-fast-tokenization.png)

> **图 2：FAST 动作 tokenization。** 它把高频动作序列变换到频域，压缩时间冗余；在控制频率升高时，朴素 OpenVLA 式分箱迅速退化，而 FAST 保持稳定。  
> 来源：FAST 论文 Figure 1，<https://arxiv.org/abs/2501.09747>

### 3.3 真正的权衡

π0-FAST 用标准 next-token prediction 取代 flow action expert，在约 10,000 小时数据上能匹配 π0，并把达到相同性能所需 GPU 小时降低约 5 倍。

但它不是“推理加速版”：自回归生成约 30–60 个动作 token 需要反复运行大 VLM，一秒动作块约需 750 ms；π0 的小 action expert 做约 10 次 flow 迭代只需约 100 ms。FAST 把主要瓶颈从训练转移到了推理，这直接引出 π0.5/KI 的混合配方。

## 4. Hi Robot 与 π0.5：从动作泛化走向开放世界泛化

### 4.1 Hi Robot：先想子任务，再执行动作

Hi Robot 将系统拆成高层 VLM 与低层 π0。高层读取场景、复杂指令和用户反馈，产生“拿起全麦面包”“不要把这个当垃圾”等短子任务；低层 π0 执行具体动作。

它首次系统展示了 PI 路线中的 System 2 / System 1 分工：高层负责语义推理与交互，低层负责实时运动控制。这个思路随后被 π0.5 融进统一模型的训练与推理接口。

### 4.2 π0.5 的异构联合训练

π0.5 的重点不是“更多自主数据”，而是让不同知识源相互迁移：

- 约 400 小时目标移动操作数据，覆盖约 100 个住宅环境；
- 固定单/双臂机器人在更多住宅中的多环境数据；
- 实验室跨本体数据和 OXE；
- Web 图像描述、VQA 与目标定位；
- 人工标注的高层子任务、对象框；
- 后训练阶段的人类 verbal instruction。

预训练样本中约 **97.6% 并非目标移动机器人家务数据**。论文要证明的是：开放世界泛化不需要所有知识都由目标机器人亲自采集，Web 语义、其他机器人技能和多环境经验可以通过统一训练迁移到目标平台。

### 4.3 FAST 预训练 + flow 后训练

π0.5 先使用 FAST 动作 token 做 280k 步预训练，高效吸收全部异构数据；再加入 flow action expert 做 80k 步后训练。推理时模型先预测高层子任务 $\hat\ell$，再以子任务为条件生成连续动作：

$$\pi(a_{t:t+H},\hat\ell\mid o_t,\ell)=\pi(a_{t:t+H}\mid o_t,\hat\ell)\pi(\hat\ell\mid o_t,\ell)$$

![](assets/PI%20系列%20VLA%20演进%20-%20Survey/figures/03-pi05-open-world.png)

> **图 3：π0.5 在未见厨房中的长程任务。** 模型把“清理厨房”分成关柜门、物品入抽屉、擦拭洒落物和餐具入水槽等子任务，再输出连续动作。  
> 来源：π0.5 论文 Figure 2，<https://arxiv.org/abs/2504.16054>

π0.5 因而能在完全未见的厨房和卧室执行 2–15 分钟任务。消融表明：Web 数据主要提升 OOD 物体理解和高层决策，多环境与跨本体机器人数据对真实动作泛化更关键；零样本 GPT-4 高层规划反而较差，因为通用 VLM 不知道低层策略实际掌握哪些技能。

## 5. Knowledge Insulation：训练/推理解耦的稳定配方

### 5.1 既不能让 flow 梯度直接破坏主干，也不能完全冻结主干

π0 的连续专家会把随机初始化模块产生的梯度传回 VLM，损伤语言与 Web 知识；完全冻结 VLM 又会使其表征无法适应机器人控制。Knowledge Insulation 的核心是：

- VLM 主干由普通 VLM 数据、robot planning 文本与 FAST 动作 token 更新；
- action expert 可以读取主干的 K/V 表征；
- flow loss 到主干的路径 stop-gradient，只更新 action expert；
- 推理时丢弃 FAST 自回归输出，只用 action expert 生成连续动作。

因此，FAST 在训练时充当**动作表征学习目标**，flow expert 在推理时充当**快速连续控制器**。这是 PI 系列最重要的架构收敛：离散动作和连续动作不再是二选一，而是分别服务训练与部署。

### 5.2 效果与代价

KI 的收敛速度接近 π0-FAST，推理速度接近 π0，并显著改善语言跟随和未见物体泛化。代价是单步训练计算约增加 20%，且工程上要维护两套动作表示、注意力 mask 和梯度路径。

## 6. RTC：实时性不是只靠缩小模型

### 6.1 Action chunk 仍有延迟问题

动作块能减少推理调用频率，却不能消灭模型延迟。若同步等待新 chunk，机器人会停顿；若直接异步切换，新旧 chunk 可能来自不同策略模式，造成位置、速度和加速度跳变。

RTC 在机器人执行当前 chunk 时生成下一 chunk，并把推理期间必然执行的旧动作作为新 chunk 的冻结前缀；其余部分使用 flow inpainting。它不修改模型权重，也不需要重训。

### 6.2 从 inference-time RTC 到 training-time RTC

原始 RTC 需要在采样时计算 guidance，增加推理开销。后续工作在训练中直接模拟延迟，让模型学习 action-prefix conditioning，移除运行时反向计算。π0.7 明确采用 training-time RTC，在训练中模拟 0–12 个控制步、最高约 240 ms 延迟。

这条支线的重要意义是：PI 不把实时性简单等同于“把模型做小”，而是把它当成异步控制与动作连续性问题。

## 7. π0.6 与 π*0.6：从模仿学习进入经验强化

### 7.1 π0.6 基座

π0.6 使用 Gemma 3 4B VLM（含约 400M 视觉编码器）和 860M flow action expert，总体约 5B。它继续采用 FAST 与连续动作双表示、Knowledge Insulation、高层子任务预测，并扩展了机器人数据与条件信息。

### 7.2 为什么 imitation 不够

机器人策略的小误差会改变环境状态，进入示范数据没有覆盖的区域；随后错误继续累积。静态文本生成中的一个错误不会改变外部世界，而机器人控制中的错误会主动制造新的分布偏移。因此，单纯行为克隆很容易达到“有时成功”，却很难达到工业部署所需的高可靠性和高吞吐。

### 7.3 Recap：示范、纠正和实践

π*0.6 的星号表示它经过 Recap 强化学习。Recap 给动作生成增加 `Advantage: positive/negative` 条件：

1. 用多任务、多机器人数据训练 distributional value function；
2. 根据回报与 value 计算 advantage，并按任务阈值二值化；
3. 预训练同时学习普通行为分布与 advantage-conditioned 分布；
4. 针对具体任务先使用示范 SFT；
5. 部署收集自主 rollouts、成功/失败标签与人工 intervention；
6. 分批重新训练 value 和策略，再次部署。

![](assets/PI%20系列%20VLA%20演进%20-%20Survey/figures/04-pistar06-recap.png)

> **图 4：π*0.6 的 Recap 架构。** Value function 把自主执行与纠正数据转成优势标签，VLA 在离散和连续两条动作路径上学习高优势行为。  
> 来源：π*0.6 论文模型图，<https://arxiv.org/abs/2511.14759>

Recap 在 espresso、洗衣和纸箱组装上把部分最难任务的吞吐量提高到 2 倍以上，失败率约减半。但它不是全自动在线 RL：奖励标签、人工纠正、环境 reset 和分批重新训练仍需要人工基础设施。

## 8. π0.6 之后的三条能力支线

### 8.1 MEM：长短期记忆分工

π0.6-MEM 把历史拆成两个尺度：

- **短期视频记忆**：因果时间注意力保存最近几秒至约一分钟的视觉与本体状态，用于遮挡、失败重试和策略切换；
- **长期文本记忆**：递归更新的压缩摘要记录“哪些步骤已经完成”，覆盖最长约 15 分钟任务。

短期窗口预训练约 5 秒，后训练可扩展到 18 帧、约 54 秒。π0.7 继承的是 MEM 的视频历史编码与连续状态 token，而不是把 π0.6-MEM 的完整高低层系统原样复制。

### 8.2 Human-to-Robot：人类视频迁移存在涌现阈值

PI 把人类视频视为一种新 embodiment：用 3D hand track 表示低层末端轨迹，用密集语言标签表示高层子任务。实验发现，只有机器人预训练覆盖足够多任务、场景和本体后，人类与机器人 latent 才自然对齐；此时加入人类视频，才能把只在人类数据中出现的泛化设置性能提升到接近 2 倍。

这说明“人类视频能否帮助机器人”不只取决于视频标注方式，也取决于基座是否已经跨过表示多样性的阈值。

### 8.3 RL Token：精密任务的轻量在线适应

Recap 会更新大型 advantage-conditioned VLA，适合从大规模部署经验中改进任务策略；RL Token 则从冻结 VLA 内部提取紧凑表示，训练小型 actor-critic 头，并正则约束 actor 不要偏离基座动作。

它在螺丝、扎带、充电器和网线插入上，用几分钟至几小时真机练习把关键阶段加速最多 3 倍。RLT 是任务专精与“最后毫米”优化支线，不是 π0.7 的主体架构或新版本代号。

## 9. π0.7：用多模态条件给异质数据消歧

### 9.1 架构继承关系

π0.7 仍是约 5B：Gemma 3 4B VLM + 860M action expert，并继承 Knowledge Insulation、flow matching、视频历史和 training-time RTC。真正的核心变化是多模态上下文：

$$\mathcal C_t=\{\ell,\hat\ell_t,\mathbf g^\star,m,c\}$$

其中：

- $\ell$：总体任务；
- $\hat\ell_t$：当前语义子任务；
- $\mathbf g^\star$：视觉子目标；
- $m$：速度、质量和错误元数据；
- $c$：`joint` 或 `ee` 控制模式。

### 9.2 为什么元数据如此关键

π0.7 的数据包括高质量示范、普通示范、失败、自主评估轨迹、π*0.6 专家轨迹、人类视频和 Web 数据。直接行为克隆会把不同策略和质量平均起来。π0.7 用元数据告诉模型每段数据“做得多快、质量多高、是否正在犯错”，训练时可以吸收低质量和失败数据扩大状态覆盖，推理时再条件到“高质量、快速、无错误”。

数据消融表明：没有元数据时，加入更多低质量数据可能使性能下降；有元数据时，即使平均质量下降，增加数据仍能持续提高性能。

### 9.3 视觉子目标与 world model

独立 world model 根据当前观测、子任务和元数据生成多视角未来图像，表达“下一阶段成功后应该长什么样”。它初始化自 BAGEL 14B，但不包含在约 5B 的 VLA 参数量中。

视觉子目标补充了文本难以表达的空间细节，如夹爪应抓把手的哪个位置、折叠后的衣物外观和物体最终布局。高层策略、world model 与低层 VLA 异步运行，因此 π0.7 应理解为一个协同系统，而不是一个完全单体的 5B 网络。

> **图 5：π0.7 总览。** 示范、自主机器人数据、Web 数据和第一视角人类视频，通过语言、视觉子目标和 episode metadata 被统一到可操控 VLA 中；推理时由高层策略、world model 与目标元数据共同调节动作。

### 9.4 代表性结果与能力边界

在没有衣物折叠训练数据的双臂 UR5e 上，π0.7 的 T 恤折叠成功率为 80.0%，接近资深遥操作员首次尝试的 80.6%。它无需任务微调即可在 espresso、洗衣和纸箱组装上接近 π*0.6 专家，也能重组子技能尝试空气炸锅、法压壶等训练中未作为完整任务出现的行为。

但“emergent”需要克制理解：这些表现更像是从海量数据中重新组合已有子技能，而不是凭空发明动作。论文明确指出，分布内已见任务经常超过 90%，未见任务或未见“任务—本体”组合通常仍约 60%–80%；较复杂的新增长程任务仍依赖人类逐步 language coaching。

## 11. 开源、复现与产品化状态

### 11.1 截至 2026-10-20 的开放情况

- openpi 已公开代码和基础权重：**π0、π0-FAST、π0.5**；
- **π0.6、π*0.6、π0.6-MEM、π0.7** 未公开权重；
- openpi 的基础 checkpoint 均声称在 10,000+ 小时机器人数据上预训练；
- 公开仓库可用于推理和微调，但官方明确提示，模型最初为内部机器人开发，迁移到 ALOHA、DROID 或自研机器人并不保证成功。

### 11.2 Pi API beta 不是 π0.8

2026-10-13 发布的 Pi API beta 提供“上传数据—托管微调—云端推理”的闭环。官方只称提供 latest models，没有宣布 π0.8 等新代号。因此它代表部署和商业接口演进，而不是新的研究模型世代。

网络连接、云端延迟、封闭权重和无法独立复现仍是其现实边界。

## 12. 综合判断

### 12.1 已经确立的事实

1. **离散和连续动作并不是非此即彼。** FAST 适合给 VLM 主干提供稳定、高信息密度的动作学习信号；flow expert 适合低延迟连续控制。KI 把两者组合成稳定配方。
2. **开放世界泛化主要来自数据互补，而非目标机器人数据堆积。** π0.5 的目标移动家务数据只占预训练样本很小部分，多环境、跨本体和 Web 数据承担不同的知识迁移角色。
3. **行为克隆无法自动解决部署可靠性。** Recap 和 RL Token 都说明，成功率、速度和最后毫米精度需要部署后的实践与强化学习。
4. **失败数据是否有用，取决于是否给它消歧。** π0.7 的元数据让失败和低质量轨迹成为状态覆盖，而不是把坏行为直接混入目标策略。

### 12.2 我的判断

PI 路线最重要的成果不是某个 benchmark 数字，而是逐步形成了一套机器人基础模型 recipe：

> Web/VLM 预训练提供语义世界知识；FAST 提供稳定动作表征；flow expert 提供连续控制；KI 管理梯度冲突；异构机器人数据提供跨本体技能；RTC 处理实时执行；Recap/RLT 负责部署后优化；MEM 与视觉子目标补齐历史和未来上下文。

这套 recipe 很可能比某一代具体模型更有长期影响。但 π0.7 仍不是产品级“万能机器人大脑”：未见组合的 60%–80% 成功率对研究很强，对无人值守部署仍不够；完整系统依赖高层策略、world model、元数据标注、语言 coaching 和人类反馈，复杂度只是从手工技能工程转移到了数据与模型编排。
