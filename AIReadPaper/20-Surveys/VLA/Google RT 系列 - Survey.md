# Google RT 系列：从规模化控制到 VLA、跨本体、数据闭环与语言动作层级

## 基本信息

- **覆盖工作**：[[RT-1 - 大规模真实机器人控制的Robotics Transformer]]、[[RT-2 - Web知识迁移视觉语言动作模型]]、[[RT-X - 跨本体机器人数据与模型]]、[[RT-Trajectory - 轨迹草图条件任务泛化]]、[[SARA-RT - 机器人Transformer线性注意力加速]]、[[AutoRT - 基础模型编排机器人数据收集]]、[[RT-H - 语言动作层级与干预学习]]
- **时间范围**：2022-12 至 2024-03（按 arXiv 初版）
- **主线**：模型架构 → Web 语义迁移 → 跨本体机器人数据 → 运动条件接口/推理效率/自主采集 → 动作层级与干预学习
- **结论边界**：系列证明视觉、语言、动作和多机器人数据可以进入统一 Transformer 体系，但并未解决完全新本体零样本控制、真正新动力学获取、高频本地部署和无需人类的安全自我改进。

## 一句话结论

Google RT 谱系不是单纯把 RT-1 按参数放大，而是围绕一个持续转移的瓶颈展开：RT-1 用 130k 真实演示确立“视觉+语言→离散动作”的规模化配方；RT-2 用 Web VLM 把开放语义接入低层控制；RT-X 用 OXE 把机器人动作经验扩展到多本体；RT-Trajectory、SARA-RT、AutoRT、RT-H 分别补上“语言说不清新运动”“大模型跑不快”“真实数据采不够”“扁平动作难共享且难纠正”四个缺口，最终形成数据、表示、模型、部署和人类反馈互相依赖的 VLA 系统观。

## 1. 领域要解决的根本问题

### 1.1 从单任务策略到通用机器人基础模型

传统机器人学习将每个任务视为独立项目：采专用演示、训练专用视觉策略、部署到固定机器人。Google RT 系列试图复用视觉/NLP 的基础模型经验，让一个策略从大量异质数据中学习共享规律，并以自然语言接受新任务。与纯 VLM 不同，机器人模型还必须满足四项硬约束：动作必须物理可执行；控制必须闭环实时；真实数据昂贵且分布长尾；错误可能造成现实风险。

因此“通用”至少包含五个维度：

1. **任务**：同一模型执行多类技能；
2. **语义**：理解未在机器人演示中出现的对象、符号和语言；
3. **运动**：重组或外推训练外轨迹；
4. **本体**：共享不同机器人经验；
5. **环境**：在新背景、建筑、物体和接触动力学中稳定执行。

系列中没有一篇同时解决五项。其价值在于逐篇把“泛化”拆开并测量。

### 1.2 瓶颈为什么不断转移

RT-1 把模型和机器人数据规模做大后，语义覆盖不足暴露；RT-2 引入 Web 知识后，发现新语义不能变成新运动；RT-X 扩展动作数据后，又发现小模型无法吸收异构本体；SARA-RT 让大模型更快，但加速不等于数据更好；AutoRT 扩大野外采集，却产生大量低成功率、每任务稀疏的数据；RT-H 用语言动作提高共享和纠正效率，但仍依赖 55B 模型和目标本体数据。

关键规律是：**上一代不是“解决完问题”，而是把主要瓶颈从一个层面推到下一个层面。**

## 2. 问题演化与时间线

### 2.1 第一阶段：建立规模化真实机器人 Transformer（2022-12）

[[RT-1 - 大规模真实机器人控制的Robotics Transformer]] 用 13 台机器人、17 个月、130k 演示和 744 个任务，构建 35M 参数实时策略。其配方是 EfficientNet-B3 + FiLM 语言注入 + TokenLearner + decoder-only Transformer + 每维 256-bin 离散动作。seen 97%、未见指令 76%，证明多任务数据和紧凑 Transformer 能在真实机器人上成立。

![](../../10-Papers/VLA/assets/RT-1%20-%20大规模真实机器人控制的Robotics%20Transformer/figures/01-overview.png)

> **RT-1 代表图。** 它把数据集、架构和真实评测同时规模化，确立后续 RT 系列的动作 token、语言条件和真机闭环基线。图片直接引用 RT-1 精读附件，未复制。

新瓶颈：USE 和 ImageNet 表征只能理解机器人数据附近的概念，开放世界语义不足；主数据仍是单一移动机械臂与厨房域。

### 2.2 第二阶段：把 Web 知识直接接入低层动作（2023-07）

[[RT-2 - Web知识迁移视觉语言动作模型]] 将动作写成 VLM 文本 token，在 PaLI-X 5B/55B 与 PaLM-E 12B 上共同微调 Web VQA 和机器人轨迹。它把 “Vision-Language-Action” 变成明确范式：同一输出头生成文字或动作，控制任务用合法动作词表约束解码。

![](../../10-Papers/VLA/assets/RT-2%20-%20Web知识迁移视觉语言动作模型/figures/01-overview.png)

> **RT-2 代表图。** 动作被视为另一种语言，互联网视觉语言任务与机器人行为克隆共享参数。图片引用 RT-2 精读附件。

结果显示 seen 约 91–93%，与 RT-1 相当；未见对象/背景/环境平均 62%，约为 RT-1 32% 的两倍；语义涌现平均最高 60%，RT-1 为 17%。但论文明确：Web 预训练只改变“何时对什么使用已学动作”，不产生擦拭、折叠、工具使用等新运动。

### 2.3 第三阶段：机器人数据从单本体扩展到多本体（2023-10）

[[RT-X - 跨本体机器人数据与模型]] 建立 Open X-Embodiment：100 万+ 轨迹、60 个数据集、22 种本体、527 个技能，并用 RLDS 统一存储。模型实验在 9 种机械臂混合上训练 RT-1-X/RT-2-X。

![](../../10-Papers/VLA/assets/RT-X%20-%20跨本体机器人数据与模型/figures/01-dataset-overview.png)

> **RT-X 代表图。** 同一仓库汇聚不同实验室、相机、机器人和动作语义，数据异质性远大于单一 benchmark。图片引用 RT-X 精读附件。

RT-1-X 在小数据域均值 63%，高于各域原方法 41% 和单域 RT-1 44%；在大数据域却欠拟合。55B RT-2-X 才能恢复并利用异构数据，在 Google Robot 上把来自其他本体的技能成功率从 RT-2 的 27.3% 提到 75.8%。新瓶颈转为模型容量、动作语义粗对齐和完全新本体泛化。

### 2.4 第四阶段：三条并行补线（2023-11 至 2024-01）

#### 2.4.1 运动条件补线：RT-Trajectory（2023-11）

[[RT-Trajectory - 轨迹草图条件任务泛化]] 发现语言条件在运动空间过于欠定，提出把末端 2D/2.5D 轨迹、时间和抓放标记画成视觉 prompt。相同 73k 演示下，7 个训练外任务成功率 67%，高于 RT-1 17%、RT-2 11%、目标图像 26%。

![](../../10-Papers/VLA/assets/RT-Trajectory%20-%20轨迹草图条件任务泛化/figures/01-overview.png)

> **RT-Trajectory 代表图。** 训练用 hindsight 自动标注，推理可接人画、视频、LLM waypoint 或图像生成模型。图片引用对应精读附件。

它证明“条件表示”与模型规模同等重要，也为 VLA 引入类似语言 prompt 的几何 motion prompt。

#### 2.4.2 效率补线：SARA-RT（2023-12）

[[SARA-RT - 机器人Transformer线性注意力加速]] 用 up-training 将已有 softmax 策略转换为可学习核化线性注意力。PaLI-X 5B 单帧 forward 从 53.2 ms 降到 45.7 ms，平均成功率 65.8% 与 65.1% 基本持平；点云 PCT 在长序列上约保持 100 ms。

![](../../10-Papers/VLA/assets/SARA-RT%20-%20机器人Transformer线性注意力加速/figures/04-sara-rt2-architecture.png)

> **SARA-RT 代表图。** SARA 只替换每帧 ViT，自注意力 fuser 仍保留 softmax，说明这是可渐进部署的局部改造。图片引用对应精读附件。

它回应 RT-2/RT-X 的计算压力，但 14% 是局部 forward 改善，不等于完整系统高频化。

#### 2.4.3 数据闭环补线：AutoRT（2024-01）

[[AutoRT - 基础模型编排机器人数据收集]] 将 VLM 描述、LLM 任务生成、机器人宪法、affordance 过滤和多策略调度组成采集系统。7 个月、4 栋楼、53 台参与机器人收集 77k episodes 与 6650+ 指令。

![](../../10-Papers/VLA/assets/AutoRT%20-%20基础模型编排机器人数据收集/figures/01-system-overview.png)

> **AutoRT 代表图。** 基础模型负责发现和提议，脚本/RT-2/遥操作负责执行，人工和硬安全仍在环。图片引用 AutoRT 精读附件。

重要负结果是 RT-2 野外采集成功率仅 4.7%，脚本为 21%，遥操作为 82%。AutoRT 扩大的是场景和任务覆盖，并未解决低层可靠性；RT-1 共同微调后高度抓取仅从 0 到 12.5%、擦拭从 10 到 30%。

### 2.5 第五阶段：把语言放进动作层级与纠正接口（2024-03）

[[RT-H - 语言动作层级与干预学习]] 在高层任务和低层动作之间插入 language motion。PaLI-X 55B 分两次查询：$\pi_h(o,g)\to z$，再 $[1m\pi_l(o,g,z)\to a[0m$。自动标签从 9 个动作维组合出 2500+ 短语。

![](../../10-Papers/VLA/assets/RT-H%20-%20语言动作层级与干预学习/figures/02-method.png)

> **RT-H 代表图。** 可读 motion 同时作为跨任务共享瓶颈、人类在线纠正接口和只更新高层 query 的训练信号。图片引用 RT-H 精读附件。

在 100k Diverse+Kitchen 数据上，RT-H 比 RT-2 平均高 15 点、action MSE 低约 20%；30 条纠正/任务把平均成功率从 40% 提到 63%，同量 RT-2-IWR 从 25% 降到 13%。新瓶颈是 motion 抽象层选择、双查询延迟、坐标语言跨本体一致性和绝对成功率。

## 4. 三条技术主轴

### 4.1 数据主轴：130k 单本体 → 1M 多本体 → 持续野外采集

RT-1 说明数据多样性比同任务重复数量更重要；RT-X 把多样性扩展到实验室和本体；AutoRT 尝试主动产生下一批数据。三者共同揭示“规模”至少有三种：轨迹数、任务/场景覆盖和本体覆盖。只增加第一种容易形成同质数据。

尚未闭合的环是：AutoRT 按 embedding 距离采集“新颖数据”，RT-X 按统一格式联合训练，但没有根据当前模型不确定性、失败簇或技能缺口决定采什么。真正数据飞轮应是：模型评测 → 识别能力边界 → 安全定向采集 → 质量筛选/纠正 → 更新模型 → 再评测。

### 4.2 表示主轴：语言任务 → 动作 token → 轨迹 prompt / language motion

RT-1/2 用高层语言描述目标，动作直接离散。RT-Trajectory 和 RT-H 分别插入连续几何与离散语义中间层：

- 高层语言回答“做什么”；
- 轨迹草图回答“末端大致经过哪里”；
- language motion 回答“当前局部怎样动”；
- 动作 token 回答“本控制周期执行多少数值”。

两篇不是竞争关系。草图跨多个时刻表达整体形状，motion 每步可纠正且上下文解码。未来层级可写成：

$$g\rightarrow c^{traj}\rightarrow z_t\rightarrow a_t$$

但层级越多，错误传播和推理延迟越大，需要不确定性与人类介入机制。

### 4.3 模型与部署主轴：小型专用 Transformer → 大 VLM → 后训练高效化

RT-1 用 TokenLearner 在长度侧做压缩；RT-2 用 55B 容量换语义，转向云端推理；RT-X 证明多本体异质性确实需要容量；SARA-RT 再把注意力改为线性；RT-H 的双查询又增加负担。系列反复展示能力—延迟 trade-off，没有一劳永逸方案。

更现实的系统可能采用分层频率：大 VLM 低频更新任务/运动条件，小型策略或动作块高频执行；必要时用蒸馏、量化、缓存和线性注意力。这样比让 55B 每个控制 tick 都完整前向更符合机器人实时性。

## 5. 实验体系如何变化

### 5.1 从 seen/unseen 指令到多轴泛化

RT-1 的 unseen 主要是已见技能与对象的新组合；RT-2 加入未见对象、背景、环境、符号、数学、多语言和人物；RT-X 加入跨本体技能；RT-Trajectory 直接评估训练外运动；RT-H 加入新对象、新建筑和少量纠正下的新任务。评测维度逐步从“语言组合”扩展到“语义、几何、动力学、本体和交互”。

### 5.2 从成功率到系统指标

SARA-RT 增加 latency；AutoRT 增加吞吐、多样性、可行性、安全 recall；RT-H 增加 action MSE、纠正样本效率和可解释中间状态。机器人基础模型成熟不能只看成功率，还需：P95 延迟、人工分钟/成功 episode、危险漏检率、每技能有效样本、跨本体适配成本和失败可诊断性。

### 5.3 仍缺少的共同 benchmark

各篇多用 Google Robot 但数据子集、模型、场景和任务不同，不能简单按百分比排名。系列仍缺：统一真机评测协议、完全留出本体、长时任务、接触动力学 OOD、统计置信区间、能耗和安全事件标准。后续 RoboArena 类平台正试图解决这一缺口，但不属于本综述七篇原始证据。

## 6. 消融实验给出的共同规律

### 6.1 数据多样性只有在模型能吸收时才有效

RT-1 显示砍任务多样性比等量砍样本更伤泛化；RT-X 又显示 35M RT-1-X 在大数据域欠拟合，55B 才受益。结论不是“数据越多越好”，而是数据覆盖、容量和采样平衡必须匹配。

### 6.2 预训练知识需要在机器人训练中被保护

RT-2 5B 从零训练未见平均仅 9%，共同微调优于仅机器人微调；RT-X 5B 从零在 emergent skills/泛化为 0/1。Web 预训练是开放概念能力的必要条件。随着机器人混合更丰富，持续混 Web 的边际收益会变化，说明配比应动态调节。

### 6.3 中间表示可以比加参数更直接地扩大任务范围

RT-Trajectory 在 RT-1 级骨干上把新任务从最佳 baseline 26% 提到 67%；RT-H 在相同 55B 骨干上比 RT-2 高 15 点。两者都说明：当条件空间与动作空间错位时，单纯放大模型不如改变监督结构。

### 6.4 人类反馈应尽量发生在压缩、可解释空间

RT-H 的 motion 纠正 40→63%，RT-2-IWR 25→13%；AutoRT 的 teleop 虽成功率高，却是最稀缺资源。未来一人多机系统应把人类用于关键 decision/motion 纠正，而不是持续接管每个动作。

## 7. 当前正在攻坚的问题

### 7.1 新运动和真实动力学

证据来自 RT-2 limitation 和 failure cases：Web 语义不能提供折叠、擦拭、工具使用和未见推动动力学。RT-Trajectory 可指定路径，但仍依赖已有动作分布与视觉反馈。未来需人类视频、仿真、触觉、世界模型和定向真机数据共同补齐。

### 7.2 完全新本体泛化

RT-X 明确未研究新机器人。粗 7-DoF 归一化在训练本体间有效，却不处理不同运动学、夹爪、双臂、腿式平台和坐标语义。Language motion、对象相对 3D 路径和显式 embodiment representation 是可能方向。

### 7.3 高频、低成本、本地推理

RT-2 55B 依赖云端 1–3 Hz；SARA-RT 只在线性化 ViT，forward 改善 14%；RT-H 双 query 进一步加重。量化、蒸馏、动作分块、多速率层级和边云协同仍是核心。

### 7.4 安全且可持续的自我改进

AutoRT 宪法提升安全任务比例，但不能保证；RT-H 纠正提高样本效率，但 action query 失败时人类仍受限。系统需要硬件 shield、形式化约束、可审计任务生成、失败数据学习和明确的人类接管协议。

### 7.5 评测与统计

多篇真机评测总 trial 很多，但分到每条指令的次数少。需要统一置信区间、场景复现、长期退化和跨实验室可比性。没有可靠评测，数据飞轮可能优化错误代理指标。

## 8. 已确立事实与推测

### 8.1 已由论文证据支持

- 大规模多任务真实演示可训练单一闭环 Transformer；
- Web VLM 预训练显著提升语义和视觉 OOD，但不自动产生新运动；
- 其他机器人数据可向目标机器人迁移技能，前提是容量和目标本体数据足够；
- 轨迹草图比高层语言更适合指定训练外几何运动；
- 已训练 softmax 策略可通过 up-training 转成更高效线性注意力并大体保持质量；
- 基础模型可编排多机器人采集，但低层自主成功率仍低且安全需人工/硬约束；
- Language motion 层级可提高多任务共享和少量纠正学习效率。

### 8.2 仍属推测或待验证

- 将 RT-Trajectory 与 RT-H 组合会优于任一单独方法；
- Language motion 能成为真正跨本体统一动作空间；
- AutoRT + RT-X 能形成无人工的数据飞轮；
- SARA、量化和蒸馏足以让 55B VLA 本地高频运行；
- 更大 VLA 会自然解决动力学和灵巧操作；
- 多层自然语言 CoT 在低层控制中一定比非语言 latent 更安全。

## 9. 复现路线与成本分层

### 9.1 最低成本：验证表示与训练配方

使用公开 OXE 子集和小型开源 VLM，复现动作 token、co-fine-tuning、轨迹通道和 language motion 自动标签；在仿真或单机械臂比较 flat/trajectory/hierarchy。重点保持数据、骨干和训练步数一致。

### 9.2 中等成本：单机闭环与人类纠正

部署 3B–7B VLA 或蒸馏策略，加入合法动作约束、异步 motion query、GUI 草图和键盘纠正。评估成功率、P95 延迟、每次成功所需人工秒数，以及未见对象/场景/运动。

### 9.3 高成本：跨本体和数据闭环

需要多机器人、RLDS 管线、策略调度、VLM/LLM 服务、长期安全运维和数据质量系统。应优先做“留一技能/本体”的小规模实验，确认正迁移后再扩大 fleet，避免只追求 episode 数。

## 10. 总结

Google RT 系列的历史可压缩为七个动词：**收集（RT-1）—迁移（RT-2）—汇聚（RT-X）—描画（RT-Trajectory）—加速（SARA-RT）—编排（AutoRT）—纠正（RT-H）**。它把 VLA 从一项模型技巧扩展为完整系统问题：数据怎样来、任务怎样表达、动作怎样共享、模型怎样运行、人类怎样介入、风险怎样控制。

最重要的判断不是“下一代一定更大”，而是基础模型必须把不同知识放在合适层：Web 数据提供语义，跨本体轨迹提供运动覆盖，轨迹草图提供几何意图，language motion 提供局部共享和纠正，低层策略负责接触执行，安全系统约束实际动作。只有这些层形成可评测、可修正的数据闭环，通用机器人策略才可能从演示型研究系统走向持续改进的现实系统。
